# SeqEvi 0.1.0 Private Cluster Ingress Runbook

> Status: active operations runbook
> Date: 2026-07-29
> Issue: FUQ-22
> Scope: Apache boundary on node4 private address `192.168.30.205`

## Boundary

The stable SeqEvi unit remains unchanged at `127.0.0.1:18081`. This runbook
exposes only its HTTP API through Apache at
`http://192.168.30.205:18082`. Never proxy PostgreSQL port `15432` and never
add an alias or static route for the artifact directory.

The listener binds only to node4's `192.168.30.205` private address. Apache
accepts only node4's observed Docker bridge range `172.17.0.0/16` or the
private LAN `192.168.30.0/24`. FUQ-22 inspection observed `172.17.0.10` for an
ordinary Cromwell-style Docker bridge worker.

## Trust Model

This minimal deployment uses the allowed cluster CIDRs as its complete trust
boundary. It has no TLS, certificate, username, password, token, or secret
mount. Do not expose port `18082` through a public route, NAT rule, load
balancer, or broader firewall rule.

The Store API accepts artifact uploads and evidence commits. Every workload in
an allowed CIDR must therefore be treated as a trusted Store writer. If
untrusted or tenant-isolated workloads later share those ranges, stop using
this ingress until an authenticated boundary is designed and deployed.

Clients need only the Store URL:

```bash
export SEQEVI_STORE=http://192.168.30.205:18082
seqevi annotate ...
```

## Install

Before changing Apache, require all preflight checks:

```bash
curl --fail --silent --show-error http://127.0.0.1:18081/health
ss -lnt | grep -F '127.0.0.1:18081'
ss -lnt | grep -F '127.0.0.1:15432'
test ! -e /etc/httpd/conf.d/seqevi-store.conf
```

Install the reviewed configuration, validate the complete Apache
configuration, and reload without restarting SeqEvi:

```bash
sudo install -m 0644 \
  deploy/httpd/seqevi-store.conf \
  /etc/httpd/conf.d/seqevi-store.conf
sudo apachectl configtest
sudo systemctl reload httpd
```

## Acceptance

From node4, preserve loopback health and confirm only the intended private
listener was added:

```bash
curl --fail --silent --show-error http://127.0.0.1:18081/health
ss -lnt | grep -F '192.168.30.205:18082'
ss -lnt | grep -F '127.0.0.1:15432'
```

From an ordinary allowed worker container on Docker bridge networking:

```bash
curl --fail --silent --show-error \
  http://192.168.30.205:18082/health

SEQEVI_STORE=http://192.168.30.205:18082 \
seqevi annotate ...

# The loopback upstream must not be reachable through node4's private address.
curl --fail --silent --show-error --connect-timeout 3 \
  http://192.168.30.205:18081/health
```

The first two operations must succeed. Direct access to port `18081` must
fail.

From a temporary worker network outside both allowed CIDRs, verify that the
proxy itself rejects access:

```bash
curl --output /dev/null --silent --write-out '%{http_code}\n' \
  http://192.168.30.205:18082/health
```

The command must print `403`. Do not treat an application `404` or connection
failure as equivalent evidence for the Apache source restriction.

## Rollback

Rollback removes only the deployment boundary:

```bash
sudo rm /etc/httpd/conf.d/seqevi-store.conf
sudo apachectl configtest
sudo systemctl reload httpd
curl --fail --silent --show-error http://127.0.0.1:18081/health
```

Do not stop SeqEvi, PostgreSQL, or alter artifacts during ingress rollback.
