# SeqEvi 0.1.0 Private Cluster Ingress Runbook

> Status: active operations runbook
> Date: 2026-07-29
> Issue: FUQ-22
> Scope: Apache boundary on node4 private address `192.168.30.205`

## Boundary

The stable SeqEvi unit must remain unchanged at `127.0.0.1:18081`. This
runbook exposes only its HTTP API through Apache at
`https://node4.cluster.local:18443`. Never proxy PostgreSQL port `15432` and
never add an alias or static route for the artifact directory.

The listener is restricted to node4's `192.168.30.205` private address. Apache
also requires the client source to be either node4's observed Docker bridge
range `172.17.0.0/16` or the private LAN `192.168.30.0/24`, and requires Basic
authentication. Both controls must pass. FUQ-22 live acceptance observed
`172.17.0.10` for an ordinary Cromwell-style Docker bridge worker.

## External Material

Provision outside the repository:

| Material | Required property |
| --- | --- |
| `/etc/pki/tls/certs/seqevi-store.crt` | certificate valid for `node4.cluster.local` |
| `/etc/pki/tls/private/seqevi-store.key` | root-readable private key |
| `/etc/seqevi/ingress.htpasswd` | generated credential, mode `0640`, readable by Apache |
| worker CA file | CA that issued the service certificate |
| worker auth file | two lines (username, password), owner-only mode |

Do not use node4's installed `localhost.localdomain` certificate: inspection on
2026-07-29 showed that it expired in 2022 and lacks the required name.

Generate the password entry without placing the plaintext password on a command
line or in shell history:

```bash
sudo install -d -m 0750 -o root -g apache /etc/seqevi
sudo htpasswd -c /etc/seqevi/ingress.htpasswd seqevi-worker
sudo chown root:apache /etc/seqevi/ingress.htpasswd
sudo chmod 0640 /etc/seqevi/ingress.htpasswd
```

The platform that launches a worker is responsible for mounting the CA and
auth file without logging their contents. SeqEvi does not define that platform
mechanism. The environment contains paths only:

```bash
export SSL_CERT_FILE=/run/secrets/seqevi-ca.crt
export SEQEVI_HTTP_BASIC_AUTH_FILE=/run/secrets/seqevi-basic-auth
export SEQEVI_STORE=https://node4.cluster.local:18443
seqevi annotate ...
```

The auth file must be a regular, non-symlink file owned by the worker process,
owner-readable, and inaccessible to group/other. Store URLs containing userinfo
are rejected. Do not put either credential in a profile, URL, command line,
WDL input, or environment variable.

For a container worker, ownership is checked against the UID of the SeqEvi
process inside that container, not the host operator by name. The secret
delivery mechanism must set the file owner to that numeric process UID (or run
the container with the intended owner UID) and mode `0400` or `0600`.

## Install

Before changing Apache, require all preflight checks:

```bash
curl --fail --silent --show-error http://127.0.0.1:18081/health
ss -lnt | grep -F '127.0.0.1:18081'
ss -lnt | grep -F '127.0.0.1:15432'
test ! -e /etc/httpd/conf.d/seqevi-store.conf
openssl x509 \
  -in /etc/pki/tls/certs/seqevi-store.crt \
  -noout -checkend 2592000 -checkhost node4.cluster.local
sudo test -r /etc/pki/tls/private/seqevi-store.key
sudo test "$(stat -c %a /etc/seqevi/ingress.htpasswd)" = 640
```

Install the reviewed configuration, validate the complete Apache configuration,
and reload without restarting SeqEvi:

```bash
sudo install -m 0644 \
  deploy/httpd/seqevi-store.conf \
  /etc/httpd/conf.d/seqevi-store.conf
sudo apachectl configtest
sudo systemctl reload httpd
```

## Acceptance

From node4, preserve loopback health and confirm only the intended private
listener was added:

```bash
curl --fail --silent --show-error http://127.0.0.1:18081/health
ss -lnt | grep -F '192.168.30.205:18443'
ss -lnt | grep -F '127.0.0.1:15432'
```

From an ordinary worker container on Docker bridge networking, mount only the
CA and mode-restricted auth file supplied by the runtime. Require:

```bash
# No CA: TLS verification must fail.
curl --fail --silent --show-error \
  https://node4.cluster.local:18443/health

# CA but no credentials: HTTP 401.
curl --cacert /run/secrets/seqevi-ca.crt \
  --output /dev/null --silent --write-out '%{http_code}\n' \
  https://node4.cluster.local:18443/health

# CA plus the SeqEvi owner-only auth-file boundary: API v1 health.
SSL_CERT_FILE=/run/secrets/seqevi-ca.crt \
SEQEVI_HTTP_BASIC_AUTH_FILE=/run/secrets/seqevi-basic-auth \
SEQEVI_STORE=https://node4.cluster.local:18443 \
seqevi annotate ...

# The loopback upstream must not be reachable through node4's private address.
curl --fail --silent --show-error --connect-timeout 3 \
  http://192.168.30.205:18081/health
```

The first and fourth commands are expected to fail. The second must print
`401`; the third must complete its bounded Store operation. Do not print or
retain either credential.

## Rollback

Rollback removes only the deployment boundary:

```bash
sudo rm /etc/httpd/conf.d/seqevi-store.conf
sudo apachectl configtest
sudo systemctl reload httpd
curl --fail --silent --show-error http://127.0.0.1:18081/health
```

Do not stop SeqEvi, PostgreSQL, or alter artifacts during ingress rollback.
