# ClaimSession Store Maintenance

Version: v1.1

Date: 2026-08-13

Status: approved candidate runbook; activation pending

Supersedes: [v1.0](20260812-v1.0-claim-session-store-maintenance.md)

1. Stop every Store service and claim-capable client and keep them stopped.
2. Verify the deployment process/writer boundary is empty (`pg_stat_activity`
   for PostgreSQL; open database/lock holders for SQLite).
3. For SQLite, resolve `--store-root` to the Store directory and the database
   URL to its existing canonical absolute `<store_root>/store.sqlite3` target.
   Refuse a missing target, URI/query ambiguity, symlink target, or any target
   other than that Store database. Record the canonical SQLAlchemy identity
   (for example, `sqlite+pysqlite:////absolute/store/store.sqlite3`), not the
   relative URL spelling.
4. Record the current revision and create a single-use acknowledgement bound to
   the canonical database identity and revision.
5. Run the explicit fenced 0004 maintenance path. Ordinary startup deliberately
   refuses this transition:
   `seqevi store-maintenance-upgrade --database-url "$SEQEVI_DATABASE_URL"
   --acknowledge-database "<canonical redacted SQLAlchemy database identity>"
   --acknowledge-revision 0003_evidence_claim_leases`. For SQLite, also pass
   `--store-root <Store directory>`.
6. Verify revision `0004_claim_sessions`, all six coordination tables, absence
   of `evidence_claim`, and unchanged sequence/artifact/evidence counts/digests.
7. Restart one service, verify `/health` and ClaimSession capabilities, then
   restore clients.

Canonical target validation and acknowledgement comparison occur before the
file fence and destructive DDL. Any identity error, timeout, uncertain commit,
unexpected schema, live writer, stale acknowledgement, or timeout-reset
readback failure is fail-closed. Keep writers quiesced and classify
revision/schema from a fresh connection.

Rollback requires the same canonical identity and fence, recreates empty 0003
coordination, and never changes terminal evidence or artifacts. With writers
still stopped, run
`seqevi store-maintenance-downgrade --database-url "$SEQEVI_DATABASE_URL"
--acknowledge-database "<canonical redacted SQLAlchemy database identity>"
--acknowledge-revision 0004_claim_sessions`; for SQLite also pass `--store-root`.
Then verify revision `0003_evidence_claim_leases`, an empty `evidence_claim`,
absence of all six 0004 coordination tables, and unchanged terminal row digests.
