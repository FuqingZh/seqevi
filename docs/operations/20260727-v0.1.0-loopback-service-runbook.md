# SeqEvi 0.1.0 Loopback Service Runbook

> Status: active operations runbook
> Date: 2026-07-27
> Issue: FUQ-12
> Scope: host rootful Docker daemon and user systemd on one trusted host

## Boundary

This runbook operates the existing passive `seqevi serve` process on host
loopback. The container owns no annotation executables or databases. It connects
only to the existing PostgreSQL metadata database and writes only to the
existing mounted artifact root.

The service has no authentication or TLS. Keep `--host 127.0.0.1`; do not expose
port 18081 to another host. Ingress, authentication, TLS, backups and monitoring
are separate work.

The user unit explicitly uses the host rootful Docker daemon through
`unix:///var/run/docker.sock`. This preserves physical host-loopback networking
and maps the configured numeric container UID/GID directly to the CephFS owner.
Do not point this unit at a rootless Docker socket.

the numeric non-root artifact owner, and an image reference pinned as
`192.168.30.202:23099/bioinfo/seqevi@sha256:<digest>`.

## Build And Push

From a clean FUQ-12 commit:

```bash
pdm install --frozen-lockfile -G dev -G server
pdm run check
pdm build
docker build --tag 192.168.30.202:23099/bioinfo/seqevi:0.1.0 .
docker push 192.168.30.202:23099/bioinfo/seqevi:0.1.0
docker image inspect \
  192.168.30.202:23099/bioinfo/seqevi:0.1.0 \
  --format '{{index .RepoDigests 0}}'
```

Record the returned repository digest. Pull and deploy that digest, not the tag.
Pushing an OCI image is independent of PyPI publishing and creates no Git tag.

If node4 cannot reach Docker Hub, seed the identical official-library base and
override only its registry location:

```bash
docker pull public.ecr.aws/docker/library/python:3.13-slim
docker build \
  --network host \
  --build-arg \
  PYTHON_IMAGE=public.ecr.aws/docker/library/python:3.13-slim \
  --tag 192.168.30.202:23099/bioinfo/seqevi:0.1.0 .
```

CI uses the canonical default `python:3.13-slim`. Record the built service image
digest regardless of which official-library registry supplied the base.

## Mandatory Preflight

Do not stop the rollback unit until every check passes.

```bash
systemctl --user status seqevi-store-fuq11.service --no-pager
systemctl --user cat seqevi-store-fuq11.service
curl --fail --silent --show-error http://127.0.0.1:18081/health

test -S /var/run/docker.sock
DOCKER_HOST=unix:///var/run/docker.sock docker info
! DOCKER_HOST=unix:///var/run/docker.sock docker info \
  --format '{{json .SecurityOptions}}' | grep -q rootless

docker inspect seqevi-postgres-fuq11
docker volume inspect seqevi-postgres-fuq11-data
docker exec seqevi-postgres-fuq11 pg_isready -U seqevi -d seqevi

findmnt --mountpoint \
  /cephfs_data/genostack_v3/genostack_php/public_file_data \
  --types ceph
stat \
  /cephfs_data/genostack_v3/genostack_php/public_file_data/database/bioinfo/stores/seqevi/artifacts
find \
  /cephfs_data/genostack_v3/genostack_php/public_file_data/database/bioinfo/stores/seqevi/artifacts \
  -type f | wc -l

deploy/systemd/verify-artifacts-mount \
  /cephfs_data/genostack_v3/genostack_php/public_file_data/database/bioinfo/stores/seqevi/artifacts \
  /cephfs_data/genostack_v3/genostack_php/public_file_data
```

Using the existing mode-`0600` PostgreSQL password file, record the Alembic
revision and row counts. Select one real `eggnog/1` or `interpro-pfam/1`
evidence key, call `POST /v1/evidence/fetch`, and retain the response plus both
artifact digests outside the repository. Verify those artifact bytes against
their database size and SHA-256 metadata.

Verify registry access before relying on it:

```bash
docker login 192.168.30.202:23099
docker pull 192.168.30.202:23099/bioinfo/seqevi@sha256:<digest>
docker image inspect \
  192.168.30.202:23099/bioinfo/seqevi@sha256:<digest>
```

## Install

```bash
install -d -m 0700 ~/.config/seqevi ~/.config/systemd/user
install -m 0600 deploy/systemd/seqevi-store.env.example \
  ~/.config/seqevi/seqevi-store.env
install -m 0644 deploy/systemd/seqevi-store.service \
  ~/.config/systemd/user/seqevi-store.service
install -d -m 0755 ~/.local/libexec/seqevi
install -m 0755 deploy/systemd/verify-artifacts-mount \
  ~/.local/libexec/seqevi/verify-artifacts-mount
```

Edit the environment file with the exact digest, existing password, exact
CephFS paths and the artifact root's numeric owner. Validate it without printing
the secret:

```bash
test "$(stat -c %a ~/.config/seqevi/seqevi-store.env)" = 600
grep -q '^SEQEVI_IMAGE=.*@sha256:' ~/.config/seqevi/seqevi-store.env
systemd-analyze --user verify ~/.config/systemd/user/seqevi-store.service
systemctl --user daemon-reload
loginctl show-user "$USER" -p Linger
```

## Cutover And Acceptance

Define a bounded readiness check in the operator shell before starting,
restarting or rolling back the service:

```bash
wait_for_seqevi() {
  attempt=1
  while [ "$attempt" -le 30 ]; do
    if curl --fail --silent --show-error \
      http://127.0.0.1:18081/health; then
      return 0
    fi
    sleep 1
    attempt=$((attempt + 1))
  done
  return 1
}
```

```bash
systemctl --user stop seqevi-store-fuq11.service
systemctl --user enable --now seqevi-store.service
systemctl --user status seqevi-store.service --no-pager
wait_for_seqevi
```

Read the actual running digest and compare it with `SEQEVI_IMAGE`:

```bash
docker inspect seqevi-store \
  --format '{{.Image}} {{.Config.Image}}'
docker image inspect "$(docker inspect seqevi-store --format '{{.Image}}')" \
  --format '{{json .RepoDigests}}'
```

Repeat the preflight cached evidence fetch and require identical evidence
metadata and artifact digests. Then verify supervision:

```bash
systemctl --user restart seqevi-store.service
wait_for_seqevi
systemctl --user is-active seqevi-store.service
```

Read back the image digest, schema revision, counts and cached evidence once
more. Keep `seqevi-store-fuq11.service` installed and inactive until acceptance
is reviewed.

## Rollback

Rollback does not change PostgreSQL or CephFS because FUQ-12 changes no schema
or evidence contract:

```bash
systemctl --user stop seqevi-store.service
systemctl --user start seqevi-store-fuq11.service
wait_for_seqevi
```

If the transient source under `/tmp/seqevi-fuq-11` is no longer intact, change
`SEQEVI_IMAGE` back to the previously accepted immutable digest and restart the
stable unit. Never recreate the PostgreSQL container or volume as a rollback
step.

## Upgrade And Diagnosis

Build and push the new version, run the full preflight, pull its digest, update
only `SEQEVI_IMAGE`, and restart the user unit. Do not use mutable tags in the
environment file.

```bash
journalctl --user -u seqevi-store.service --since today
docker inspect seqevi-store
docker logs seqevi-store
curl --verbose http://127.0.0.1:18081/health
docker exec seqevi-postgres-fuq11 pg_isready -U seqevi -d seqevi
findmnt --mountpoint \
  /cephfs_data/genostack_v3/genostack_php/public_file_data \
  --types ceph
```

The unit intentionally refuses startup when the rootful Docker socket is
missing, the artifact directory does not resolve to the exact configured CephFS
mount, the immutable image is unavailable, or Docker cannot inspect it. Resolve
the failed guard; do not bypass it.

On node4, repository validation that materializes Data Packages also needs the
host trust store selected explicitly:

```bash
SSL_CERT_FILE=/etc/pki/tls/certs/ca-bundle.crt pdm run check
```

This is an existing host CA configuration requirement for `datapackage.org`,
not a service image or SeqEvi contract change.
