# dbCAN D4 Target-Store Sizing Acceptance

Version: v1.0
Date: 2026-08-19
Status: accepted representative rates and replay; expansion headroom unavailable

## Outcome

D4 is accepted on the predeclared natural all-missing branch. One managed
dbCAN 5.2.9 invocation processed the frozen 2,729-record input with 64 adapter
threads, followed by an independent later-process replay. The primary run
computed all 2,729 keys; the replay reused all 2,729 and launched no inner
dbCAN computation. No second file, concurrency pilot, selected expansion or D3
annotation ran as part of D4.

Raw logs, result databases, resource samples and complete host readbacks remain
in the isolated evidence root. This public record retains only non-secret
identities and reconciled summaries. Acceptance covers result correctness,
Store/CAS reconciliation, replay behavior, and observed workload/rates; it
does not accept peak headroom or expansion eligibility.

## Disposition

D4 supplies dbCAN-specific single-file rates only for the measured shape: one
invocation, at most 2,729 total/missing keys, one annotation batch, and no
greater residue or length workload than this input. It does not authorize
extrapolation above those caps. Because continuous peak RSS/scratch and
CephFS-specific I/O were not captured, expansion headroom is unavailable and
all selected or concurrent expansion remains closed. A future expansion must
repeat a representative sizing gate with those metrics before applying the
key/residue/length caps or attempting a separately frozen, naturally missing,
disjoint two-process pilot. D5 remains unavailable on current claim-after-OCI
dispatch. The separate read-only
[bounded corpus manifest](20260819-v1.0-dbcan-bounded-corpus-manifest.md)
records the D4-covered file and nine unselected files without authorizing any
additional run.
