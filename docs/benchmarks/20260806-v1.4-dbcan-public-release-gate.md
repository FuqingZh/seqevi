## Subsequent Acceptance Decision

On 2026-08-07, release issue
[#20](https://github.com/FuqingZh/seqevi/issues/20) changed the 0.2.0 acceptance
policy without changing the result of this run. The node4 repeat pull of the
already-published immutable dbCAN GHCR digest is deferred as a site transport
check and is no longer a 0.2.0 blocker. The run below remains incomplete and
must not be cited as a passing Slice D run.

SeqEvi 0.2.0 includes managed setup only for dbCAN. eggNOG and InterPro/Pfam
remain supported through existing explicit and profile runtimes; managed setup
for them is later feature work. Issue #18 remains the record for the deferred
site check until the production release process disposes of it.

## Decision

Slice D did not pass. Production PyPI has no `seqevi` project or `0.2.0`
distribution. One explicitly authorized TestPyPI staging publication enabled
clean-install and controlled failure-path checks, but the acceptance host did
not complete acquisition of the wheel's bundled public GHCR digest. Setup apply
therefore never began.

The run did not build or install a wheel from the checkout, inject the issue-16
release-equivalent candidate, alter the bundled kit, remove any image, restart
Docker, or claim staging/candidate evidence as public-release evidence. The
real resource, existing user profiles, unrelated images and containers, and
the issue-16 candidate remained untouched.

## GHCR Stop Boundary

Anonymous Docker pull resolved the bundled digest and began transferring its
layers. The task's first bounded 900-second pull did not complete. A separate
user-owned pull of the same digest was already active; after the owned attempt
ended, the task terminated only its own retry wrapper before attempt two and
left the external process untouched. Exact `docker image inspect` still did not
find the digest, so setup apply remained closed. No further pull was started.

Because the image was never fully inspectable, the run did not remove it or
attempt the required exact-digest restoration proof. Partial layer transfer is
transport evidence, not an acquired public runtime.
