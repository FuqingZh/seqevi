## Boundary And Method

This read-only audit enumerated exactly the ten top-level regular FASTA files
under the operator-declared `others` corpus directory, without recursion. It
did not select an expansion, run annotation, pull an image, or mutate Store or
CAS. The raw JSON manifest remains in the isolated evidence root with SHA-256
`d42c952e864f39c2972dda6d09cc50224aeab1ee0fe82da9a7fdd44d8ad5fcae`.
Here, `unseeded/not executed` is a file-level execution disposition: it does
not claim that a read-only Store inventory proved every key in that file
missing, and it does not erase possible sequence overlap with the covered D4
set.

Each EvidenceKey set uses the accepted dbCAN ToolRuntimeDigest, ResourceID and
seven semantic parameters recorded by the
[D4 acceptance](20260819-v1.0-dbcan-d4-target-store-sizing-acceptance.md).
FASTA statistics use all parsed records for `records` and deduplicated
SequenceIDs for `unique`, residues and nearest-rank length percentiles. The
key-set digest is SHA-256 over the canonical sorted EvidenceKey JSON set.

The D4 shape caps are 2,729 total keys, 828,607 residues, maximum length 3,275,
p50/p90/p95/p99 no greater than 262/542/684/1,082, and one annotation batch
(the 10,000-key batching boundary). Passing these shape comparisons would not
authorize expansion: D4 did not capture continuous peak RSS/scratch or
CephFS-specific I/O, so headroom and expansion eligibility remain unavailable.
