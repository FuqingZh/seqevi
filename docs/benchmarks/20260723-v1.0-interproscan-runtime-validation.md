# InterProScan Pfam Runtime Validation

> Status: passed
> Date: 2026-07-23
> Last validated: 2026-07-26

## Contract

This validation closes the Phase 3 external-runtime gate for the
`interpro-pfam/1` adapter using:

- InterProScan `5.77-108.0` 64-bit;
- InterPro data release `108.0`;
- Pfam `38.1`;
- the bundled HMMER `3.3` runtime;
- local JDK `17`;
- `--applications Pfam --formats TSV --disable-precalc --cpu 8`.

The system OpenJDK 8 is too old for this release. The launcher accepts the
selected JDK 17 because its actual compatibility check requires Java major
version 11 or newer. No system Java or SeqEvi package dependency was changed.

## Validation Finding

The first real SeqEvi run correctly rejected the official output because the
fixture modeled a 13-column TSV while InterProScan `5.77-108.0` emits its
complete 15-column TSV layout. The final two columns hold GO and pathway
annotations and remain as `-` when those features are disabled.

The adapter contract was corrected narrowly:

- require the official 15-column layout;
- validate that the disabled GO and pathway columns are `-`;
- keep the existing 13-column normalized evidence schema;
- reject non-empty GO or pathway values as outside `interpro-pfam/1`.

Focused tests now use the official layout and cover rejection of undeclared GO
content. No evidence schema or semantic parameter was widened.

## Post-Hardening Named-Profile Smoke

On 2026-07-26, the published external runtime was verified with a refreshed
resource lock and a named `interpro-pfam` execution profile. The input was the
official single-protein test FASTA:

| Property | Value |
| --- | ---: |
| Input records | 1 |
| Unique sequences | 1 |
| FASTA size | 272 bytes |
| Sequence length | 248 amino acids |
| Input digest | `sha256:d30f0548b1194530538d4fdd9e36bf55c625a7d8b2882e11b763082dd492f3a6` |

The input is distributed in the official expanded kit as
`test_single_protein.fasta`; its file SHA-256 is the digest above. The smoke can
be reproduced with a fresh output root and a named profile containing the
following resolved values:

```toml
version = 1
adapter = "interpro-pfam"
executable = "/path/to/interproscan-5.77-108.0/interproscan.sh"
resource = "/path/to/interproscan-5.77-108.0/data"
threads = 8
path_prepend = ["/path/to/jdk-17/bin"]
```

Save that file as
`${XDG_CONFIG_HOME:-$HOME/.config}/seqevi/profiles/interpro-pfam-38.1.toml`,
then run:

```bash
INTERPRO_ROOT=/path/to/interproscan-5.77-108.0
JAVA_17_BIN=/path/to/jdk-17/bin
PROFILE_FILE="${XDG_CONFIG_HOME:-$HOME/.config}/seqevi/profiles/interpro-pfam-38.1.toml"
RUN_ROOT="$(mktemp -d /tmp/seqevi-interpro-profile.XXXXXX)"
INPUT="$INTERPRO_ROOT/test_single_protein.fasta"

seqevi profile validate --config "$PROFILE_FILE"
seqevi profile show interpro-pfam-38.1
seqevi profile list

seqevi annotate \
  --profile interpro-pfam-38.1 \
  --fasta "$INPUT" \
  --store "$RUN_ROOT/store" \
  --output "$RUN_ROOT/named-cold"

env PATH="$JAVA_17_BIN:$PATH" seqevi annotate \
  --adapter interpro-pfam \
  --executable "$INTERPRO_ROOT/interproscan.sh" \
  --resource "$INTERPRO_ROOT/data" \
  --threads 8 \
  --fasta "$INPUT" \
  --store "$RUN_ROOT/store" \
  --output "$RUN_ROOT/explicit-cache"

seqevi annotate \
  --profile interpro-pfam-38.1 \
  --fasta "$INPUT" \
  --store "$RUN_ROOT/store" \
  --output "$RUN_ROOT/named-cache"

sha256sum "$RUN_ROOT"/*/evidence.parquet "$RUN_ROOT"/*/no-hits.parquet
```

The output and Store paths must be new because SeqEvi does not overwrite
invocation packages or immutable evidence.

The profile selected InterProScan `5.77-108.0`, Pfam `38.1`, eight threads and
JDK 17 through `path_prepend`. Profile validation, effective display and
listing all passed before annotation.

## Decision

InterProScan `5.77-108.0` direct-tool parity is accepted for
`interpro-pfam/1`. Phase 3 is complete.

The scientific parity remains accepted. The post-hardening smoke confirms the
expanded cache identity for Java, normalized properties and `pfam_a.dat`, and
supersedes the historical identity strings for current cache use.

Thread tuning is separate from this parity result. The validation establishes
that eight-thread direct and SeqEvi executions are scientifically equivalent;
it does not claim that eight threads is the production throughput optimum.
