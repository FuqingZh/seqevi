# InterProScan Pfam Runtime Validation

> Status: passed
> Date: 2026-07-23

## Contract

This validation closes the Phase 3 external-runtime gate for the
`interpro-pfam/1` adapter using:

- InterProScan `5.77-108.0` 64-bit;
- InterPro data release `108.0`;
- Pfam `38.1`;
- the bundled HMMER `3.3` runtime;
- local JDK `17`;
- `--applications Pfam --formats TSV --disable-precalc --cpu 8`.

The system OpenJDK 8 is too old for this release. The launcher accepts the
selected JDK 17 because its actual compatibility check requires Java major
version 11 or newer. No system Java or SeqEvi package dependency was changed.

## Validation Finding

The first real SeqEvi run correctly rejected the official output because the
fixture modeled a 13-column TSV while InterProScan `5.77-108.0` emits its
complete 15-column TSV layout. The final two columns hold GO and pathway
annotations and remain as `-` when those features are disabled.

The adapter contract was corrected narrowly:

- require the official 15-column layout;
- validate that the disabled GO and pathway columns are `-`;
- keep the existing 13-column normalized evidence schema;
- reject non-empty GO or pathway values as outside `interpro-pfam/1`.

Focused tests now use the official layout and cover rejection of undeclared GO
content. No evidence schema or semantic parameter was widened.

## Decision

InterProScan `5.77-108.0` direct-tool parity is accepted for
`interpro-pfam/1`. Phase 3 is complete.

The scientific parity remains accepted. Later review hardening expanded the
cache identity to include Java, normalized properties and `pfam_a.dat`, so the
identity strings above must not be reused as current post-hardening values.

Thread tuning is separate from this parity result. The validation establishes
that eight-thread direct and SeqEvi executions are scientifically equivalent;
it does not claim that eight threads is the production throughput optimum.
