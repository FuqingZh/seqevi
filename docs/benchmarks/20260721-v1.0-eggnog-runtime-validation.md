## Findings

Real-runtime validation found and corrected three fixture blind spots:

- version probing must pass the selected `--data_dir`;
- the runtime `bin/` directory must lead `PATH` for `#!/usr/bin/env python` and
  sibling search tools;
- eggNOG-mapper v2 uses `-i` and `-m`, not `--input` and `--mode`.

The validation exposed two Phase 6 performance constraints. The adapter fixes
`--cpu 1`, making a small full-database run compute-bound, and the old
constructor rehashed about 50 GB of native database files on every invocation.
A dedicated warm-cache constructor run took 2:24.20; the full cache-only wall
time also includes lookup and package materialization. Phase 6.1 now provides
`seqevi.lock` and explicit full verification so a locked snapshot avoids those
repeated content reads. A real-database lock timing will be recorded when that
mount is available. Thread tuning remains deferred until the bounded-memory
dataflow is complete.

Raw smoke artifacts and command logs were task evidence outside the repository;
the stable inputs, checksums and conclusions are retained here.

## Named Profile Smoke

On 2026-07-24, one deterministic sequence from the accepted input set exercised
the complete named-profile workflow against the same eggNOG-mapper 2.1.13 and
eggNOG DB 5.0.2 runtime. Configuration and outputs used an isolated temporary
directory and were not retained in the repository.

The workflow is reproducible after assigning host-local accepted paths:

```bash
export XDG_CONFIG_HOME="$(mktemp -d)/config"
seqevi profile init eggnog-5.0.2 --adapter eggnog
# Edit the generated TOML with the accepted executable, resource and Store.
seqevi profile validate \
  --config "$XDG_CONFIG_HOME/seqevi/profiles/eggnog-5.0.2.toml"
seqevi profile list
seqevi profile show eggnog-5.0.2
seqevi annotate --profile eggnog-5.0.2 \
  --fasta proteins.fasta --output named-first
seqevi annotate --adapter eggnog --executable "$EMAPPER" \
  --resource "$EGGNOG_DATA" --store "$STORE" --threads 1 \
  --fasta proteins.fasta --output explicit
seqevi annotate --profile eggnog-5.0.2 \
  --fasta proteins.fasta --output named-cached
```

The second `init` attempt exited 1 without changing the file. Validation,
listing and redacted display succeeded; display reported the effective `PATH`
variable name without its value. The cold named run reported `0 cached, 1
computed` in 1:00:48 with 4,604,408 KiB peak RSS. The explicit and second named
runs each reported `1 cached, 0 computed`.

All three Data Packages had the same adapter contract, input digest, semantic
parameters, resource identity and tool runtime digest. Their canonical identity
projection had SHA-256
`8b60ebf68ff6a7d3658b84d892f23050789cf66324b4cc450a14fcf2c4444a6d`.
The three evidence Parquet files were byte-identical with SHA-256
