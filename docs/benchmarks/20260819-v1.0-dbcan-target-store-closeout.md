# dbCAN Target-Store Closeout

Version: v1.0
Date: 2026-08-19
Status: accepted scoped dbCAN gate closeout; corpus expansion closed

## Decision

The scoped dbCAN gate of the shared Store cache-seeding plan is accepted through D1,
D2, representative D4 sizing/replay, all-present D3 target replay and the D5
unavailable disposition. D4 ran before D3. No selected expansion manifest was
provided and no expansion Store-write scope was authorized, so selected
expansion and both two-file pilots were not run. They remain separate future
gates rather than implied results. This is not a corpus-complete dbCAN seeding
claim. InterPro Preflight is the next active lane.

This closeout does not rerun eggNOG C1/C2, change accepted eggNOG evidence,
start a same-key dbCAN gate, pull the public dbCAN image, change runtime code,
or broaden the public kit/profile contract.

## Accepted Execution Chain

The [D2 record](20260819-v1.0-dbcan-d2-local-candidate-acceptance.md) freezes
the released 0.3.1 scientific identity and immutable local candidate. The
[D4 record](20260819-v1.0-dbcan-d4-target-store-sizing-acceptance.md) accepts
one 64-thread, 2,729-key natural all-missing computation and independent
zero-compute replay. The [D3 record](20260819-v1.0-dbcan-d3-target-store-replay-acceptance.md)
accepts the fixed-50 exact-subset branch as two independent all-present
replays. It explicitly does not claim a cold 50-record computation.

D4 measured 450.31 seconds managed wall time, 440.09 seconds inner elapsed,
6.06 managed-wall keys/second, 174 hits and 2,555 no-hits. Thirty-second
sampling observed about 59.7 logical CPUs and 9.109 GiB container memory. Those
30-second samples are not continuous peak RSS/scratch or CephFS-specific I/O,
so expansion headroom is unavailable even though all final reserves passed.
The primary Store delta was exactly 2,729 evidence rows, zero sequence rows and two
batch artifacts totaling 22,879 bytes. D4 replay and both D3 replays produced
zero Store/CAS growth.

These rates apply only to the measured single-file shape: at most
2,729 total/missing keys, one annotation batch, 828,607 residues and the frozen
length bounds. Larger or repeated-batch inputs remain unseeded pending a new
representative sizing gate with continuous peak and CephFS I/O evidence. A
different-file two-process shape still requires
two naturally missing, mutually disjoint inputs inside every D4 cap and its own
combined headroom acceptance. No such pair was selected here.

## Explicit Unseeded Disposition

No user-approved selected-expansion manifest exists. A separate bounded,
read-only [corpus disposition manifest](20260819-v1.0-dbcan-bounded-corpus-manifest.md)
nevertheless enumerates all ten top-level regular FASTA files in the declared
corpus directory, without selecting or executing them. The auditable inventory
is:

| Input class | Frozen identity | Disposition |
| --- | --- | --- |
| D4 representative file | 2,729-key set `dbfb48e8...e00c` | seeded and replayed |
| D3 fixed 50 | 50-key set `79a2b436...e486`; exact D4 subset | covered by D4; replayed twice |
| other nine enumerated corpus files | explicit FASTA, workload and EvidenceKey-set digests in the bounded manifest | unseeded/not executed; every file exceeds at least one D4 workload cap |
| files above D4 keys/residues/length/single-batch caps | explicit per-file cap result in the bounded manifest | unseeded by policy; require larger representative sizing |

Thus the complete positively covered EvidenceKey inventory is the D4 set, with
D3 as a subset. The other nine files are not silently classified as covered:
each is explicitly unseeded/not executed and outside the accepted scope.
Before any future dbCAN expansion, the user must authorize and freeze a
selected file/input/EvidenceKey manifest; continuous peak RSS/scratch and
CephFS-specific I/O must also be captured. Until then expansion is closed, not
merely pending selection.

## D5 Unavailable Disposition

Released SeqEvi 0.3.1 source revision
`da55c14d95ef61140d3fa9c047df333aaea8798c` proves that managed-v2 dispatch
creates and starts the outer OCI container before the inner process can open a
ClaimSession. The exact release blobs are:

- `src/seqevi/distribution/oci.py` Git blob
  `3e86899417574c886238562fcc222c2244ff16da`: Docker create occurs at release
  lines 127-147 and `start --attach` at lines 154-159;
- `src/seqevi/annotate.py` Git blob
  `ac46d053df8af7fbd40188f0f4390078e5872004`: the inner annotation path opens
  ClaimSession at lines 196-197 and only then acquires keys at lines 214-224.

There is therefore no claim-before-OCI path on the released dispatch. A
same-key two-caller run could not prove that only the winner launched external
OCI computation: both callers would already have launched containers. D5 is
unavailable, no same-key process was started, and no weaker claim is presented
as passing.

## Handoff

The scoped dbCAN gate is closed at file concurrency one. The bounded corpus is
enumerated, but the nine files outside the D4 set are unseeded/not executed and
expansion is closed.
The master plan may now resume InterPro read-only Preflight. Any future dbCAN
expansion needs a new explicit manifest, Store-write authorization and the
applicable D4-shape or larger representative sizing gate.
