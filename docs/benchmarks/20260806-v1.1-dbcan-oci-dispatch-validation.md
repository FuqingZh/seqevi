> Status: Slice C dispatcher and local-image cold/cache boundary passed; public release gate pending

public GHCR package. A temporary local image was built from the locked dbCAN
inputs and an already cached local Python base. The release Dockerfile and
bundled kit manifest were not changed.

## Cold managed-v2 run

The host dispatched a one-record FASTA through the v2 OCI profile. The
container used the caller numeric UID/GID, read-only FASTA and resource binds,
a read-write local Store bind and `--network none`. It invoked the inner
`seqevi annotate` with the official dbCAN 5.2.9 launcher and the fixed
`dbcan-cazyme/1` parameters.

The run completed with:

```text
adapter: dbcan-cazyme
result schema: dbcan-cazyme/5
input records: 1
hits: 0
no-hits: 1
ToolRuntimeDigest: sha256:2ac45c301fb51a1da40c81d959cba708e5b16d77e4cae515805059ee432559da
```

The published DuckDB result was read back with the native SeqEvi scanner. It
contained the expected 17-column public relation and one terminal `no_hit`
row. The outer dispatcher removed its exact temporary container before
returning.

## Cached managed-v2 replay

The same input was run again against the same local Store through a fresh
ephemeral container. The result reported:

```text
input records: 1
cache hits: 1
computed: 0
hits: 0
no-hits: 1
```

The public annotation relation was value-equal between cold and cached files
after excluding the intentional `EvidenceSource` provenance column (`computed`
versus `cache`). No dbCAN computation was started for the replay, and no OCI
annotation container remained after cleanup.

## Boundary evidence and residual gate

Fixture tests additionally assert that the dispatcher does not mount the Docker
socket or a broad home/work directory, uses read-only FASTA/resource mounts,
passes the caller UID/GID, selects `--network none` for a local Store, rejects
credential-bearing shared URLs, validates result metadata, and removes the
exact container on completion.

This is not yet the public release gate. The remaining gate is a real
local-v1 versus managed-v2 scientific equality run on the accepted 50-record
dbCAN input, including normalized values, `ToolRuntimeDigest`, hit/no-hit
classification, DuckDB provenance and a later-process cache replay. The
temporary local image also does not validate GHCR publication, the release
base-image digest or the final public image readback. In particular, this
development image used the cached node4 Python 3.13.14 base, so its runtime
digest is not evidence of equality with the separately accepted local runtime;
the release image's pinned base must be used for that comparison.
