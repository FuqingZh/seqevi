# SeqEvi 0.1.0 Stable Loopback Service Acceptance

> Status: stable loopback service accepted
> Date: 2026-07-27
> Issue: FUQ-12
> Source commit: `b028061`

## Decision

The FUQ-11 transient source deployment was replaced by a persistent
user-systemd service on node4. The unit launches a non-root container through
the host rootful Docker daemon. The stable service uses the existing PostgreSQL
container, named PostgreSQL volume and CephFS artifact root without changing
the Store schema or evidence records.

This acceptance remains loopback-only. It does not approve ingress, TLS,
authentication, backups, Prometheus, Kubernetes or multi-host exposure.

## Rollback

The original FUQ-11 transient definition was preserved as the persistent user
unit `seqevi-store-fuq11.service` before cutover. Its source runtime under
`/tmp/seqevi-fuq-11`, PostgreSQL password file and existing data surfaces remain
intact. The rollback unit is installed and inactive while the stable unit is
accepted.

Review-hardening retries invoked the guarded rollback multiple times. One retry
treated the normal timing gap between `Type=simple` process start and healthy
application state as a failed cutover. Another selected a Docker daemon that did
not contain the accepted image. Each retry stopped the candidate stable unit,
started `seqevi-store-fuq11.service`, waited for health, and preserved the
existing PostgreSQL and artifact data. The evidence does not establish image
pruning as the cause of the missing image, so no prune causality is claimed.
