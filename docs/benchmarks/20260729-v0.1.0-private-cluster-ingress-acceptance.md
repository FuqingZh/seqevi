# SeqEvi 0.1.0 Private Cluster Ingress Acceptance

> Status: accepted pre-install evidence
> Date: 2026-07-29
> Issue: FUQ-22

## Scope

Acceptance used a temporary user-owned Apache process equivalent to the
reviewed plain HTTP deployment asset, the stable loopback SeqEvi service, and
the accepted SeqEvi image as worker context. It bound the proposed private
address and port `192.168.30.205:18082` without installing anything under
`/etc/httpd`.

The run performed only health, evidence fetch, and artifact download requests.
No PostgreSQL row, artifact, system Apache configuration, firewall rule, or
SeqEvi service was changed. The temporary Apache process and negative-test
Docker network were removed after the bounded run.

## Trust Boundary

The allowed CIDRs are the complete authorization boundary. The Store API also
supports artifact upload and evidence commit, so every process in those ranges
is trusted as a Store writer. The API's digest, schema, size, and immutability
checks remain active but do not identify the caller.

## Installation Gate

This evidence validates the candidate boundary but does not install it. After
PR review and merge, the operator must install
`deploy/httpd/seqevi-store.conf`, run `apachectl configtest`, reload Apache, and
repeat the allowed and denied worker checks against port `18082`.

The final deployed acceptance must additionally cover one controlled
miss-to-commit-to-hit cycle and an Apache restart. Those checks intentionally
remain pending because this pre-install run did not mutate the shared Store or
the system Apache service.
