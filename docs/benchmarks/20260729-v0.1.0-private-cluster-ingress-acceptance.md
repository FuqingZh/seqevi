# SeqEvi 0.1.0 Private Cluster Ingress Acceptance

> Status: accepted pre-install evidence
> Date: 2026-07-29
> Issue: FUQ-22

## Scope

Acceptance used a temporary non-privileged Apache listener equivalent to the
reviewed deployment asset, a one-run CA/certificate and Basic credential, the
stable loopback SeqEvi service, and the accepted SeqEvi image with the candidate
`src/` mounted read-only. No system Apache configuration, PostgreSQL data, or
artifact data was changed.

The temporary listener used port `18444` instead of the proposed privileged
installation at `18443`. It was removed after the bounded run.

## Runtime Evidence

| Property | Observed value |
| --- | --- |
| Host | `node4.cluster.local` |
| SeqEvi upstream | healthy at `127.0.0.1:18081` |
| PostgreSQL | listening only at `127.0.0.1:15432` |
| Worker context | ordinary Docker bridge container |
| Apache-observed worker source | `172.17.0.10` |
| Intended source ranges | `172.17.0.0/16`, `192.168.30.0/24` |
| TLS without supplied CA | rejected |
| TLS with CA, without auth | rejected with HTTP `401` |
| TLS with CA and owner-only auth file | accepted |
| Direct worker access to `192.168.30.205:18081` | rejected |

The auth file was mode `0600`, mounted read-only, owned by the numeric UID used
for the container process, and named only through
`SEQEVI_HTTP_BASIC_AUTH_FILE`. No credential was placed in a URL, profile,
command line, WDL input, or environment value.

## Installation Gate

This evidence validates the proposed boundary but does not install it. System
Apache installation still requires an operator-issued certificate and key,
owner-restricted `htpasswd`, `apachectl configtest`, privileged reload, and the
same positive/negative worker checks against port `18443`.
