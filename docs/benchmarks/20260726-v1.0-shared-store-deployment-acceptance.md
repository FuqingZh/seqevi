# Shared Store Deployment And Acceptance

> Status: canary accepted; production promotion pending
> Date: 2026-07-26
> Issue: FUQ-11
> Source baseline: `1a4cdf6`

## Decision

The implemented PostgreSQL/HTTP/POSIX shared Store is accepted for a private
single-host canary. Independent clients reused fixture, eggNOG and InterPro
evidence through the HTTP boundary, PostgreSQL survived restart, and a
PostgreSQL-plus-artifact backup restored to a second service.

This result does not approve multi-host production exposure. The v1 HTTP
service has no application authentication or TLS, and the accepted service is a
transient user unit built from a source worktree.

## Deployment

| Boundary | Accepted canary value |
| --- | --- |
| Host | `node4` |
| Service | `seqevi-store-fuq11.service` |
| HTTP | `127.0.0.1:18081` |
| PostgreSQL | PostgreSQL 18.4, dedicated container and Docker volume |
| PostgreSQL listener | `127.0.0.1:15432` |
| Database | `seqevi` |
| Artifact root | `database/bioinfo/stores/seqevi/artifacts` on CephFS |
| Schema revision | `0002_artifact_byte_size_bigint` |
| Batch limit | 1,000 |
| Artifact limit | 512 MiB |

The database credential is a generated mode-`0600` user secret and is not
retained in this document. The service owns all PostgreSQL and shared artifact
writes; annotation clients receive only the HTTP URL.

An empty database migrated to the schema head. Repeated service startup left
the migration unchanged. `/health` returned HTTP 200 before and after both
service and PostgreSQL restarts.

## PostgreSQL Contract

All three tests marked `requires_postgres` passed against a dedicated
`seqevi_test` database:

- migration from the original integer artifact size to `bigint`;
- HTTP commit, lookup and fetch;
- two concurrent identical commits producing one `created` and one `existing`
  outcome.

The tests now create a unique PostgreSQL schema per test and drop it on exit.
This was added after the initial acceptance run showed that the service and
concurrency tests otherwise left metadata referencing pytest temporary
artifacts in the supplied database. The corrected run left zero application
tables and zero temporary schemas in `seqevi_test`.

The shared Store contract suite also covers invalid digests, sizes and paths,
missing artifacts, corruption, payload conflicts and configured request
limits.

## Deterministic Fixture Baseline

The benchmark used deterministic unique fixture sequences and opened a new
Store client for each cold, cached and mixed phase. The local and HTTP runs
produced byte-identical six Parquet artifacts and three sequence maps.

| Store | Sequences | Cold A | Cached B | Mixed C | Total wall | Peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Local | 10,000 | 15.74s | 2.40s | 10.53s | 29.91s | 1,222,100 KiB |
| HTTP shared | 10,000 | 77.39s | 6.74s | 38.24s | 122.82s | 1,371,384 KiB |

Phase counts were identical:

- A: 10,000 computed;
- B: 5,000 cached and zero computed;
- C: 5,000 cached and 5,000 computed.

The HTTP path processed 25,000 phase inputs at 203.6 inputs/s end to end, while
the local path processed them at 835.8 inputs/s. The shared run was 4.11 times
the local wall time. The dominant HTTP cold cost was commit: 58.97 seconds of
the 77.39-second A phase. This is an acceptance baseline, not a throughput
target; reducing per-artifact and per-evidence request overhead is the next
performance opportunity.

A separate 100-sequence HTTP smoke completed in 11.04 seconds with the expected
100-computed, 50-cached and 50/50 mixed phase counts.

schema is a release-readiness item.

## Recovery Rehearsal

The service was stopped at a consistency boundary, then PostgreSQL and the
artifact tree were backed up:

| Asset | Size | SHA-256 |
| --- | ---: | --- |
| PostgreSQL custom dump | 1,937,249 bytes | `f8900f89a721bc378e63fc7b2c9523f2c1cf81f1d81759bcb0255f0adde7a7c4` |
| Artifact tar | 727,040 bytes | `7eb81cc49988453f8bda0d0101f9cabf3167edfe4542153b7dd3b99fc9a7d8b9` |

The snapshot restored into a separate database and artifact root with schema
revision `0002_artifact_byte_size_bigint`, 15,152 sequences/evidence records,
12 artifact records and 12 matching files. A second service on
`127.0.0.1:18082` returned the InterPro result as a complete cache hit in 6.49
seconds. That temporary restore service was then stopped.

The rehearsal snapshot preceded the final eggNOG smoke, so it proves the
procedure and consistency boundary rather than serving as the final current
backup.

The terminal live Store contained:

| --- | ---: |
| `fixture/1` | 15,151 |
| `eggnog/1` | 1 |
| `interpro-pfam/1` | 1 |

PostgreSQL held 15,153 sequences, 15,153 evidence records and 14 artifact
records totaling 714,196 bytes. The CephFS root contained exactly 14 files.
Every database artifact reference existed and matched both its recorded size
and SHA-256 digest.

The repository release gate completed with formatting, lint and type checks
clean and all 136 tests passing on Python 3.13.11. The three PostgreSQL tests
ran against the real dedicated test database; none were skipped. Two upstream
dependency warnings remain: the Data Package model's `schema` field shadowing
and Starlette's deprecated `httpx` TestClient integration.

## Residual Risks And Promotion Gate

The canary remains loopback-only. Production promotion requires:

- a stable package or immutable service image and a persistent supervised unit;
- authenticated private ingress and an explicit TLS policy;
- managed secret rotation rather than a host-local credential file;
- scheduled coordinated PostgreSQL/artifact backups and a final-snapshot
  restore rehearsal;
- health, capacity, latency and artifact-integrity monitoring;
- removal or explicit management of the external schema network dependency;
- ownership and runbook decisions for service, database and CephFS storage.

The benchmark identifies HTTP commit overhead as the first optimization target.
It does not justify changing the frozen evidence model or allowing clients to
write PostgreSQL or CephFS directly.
