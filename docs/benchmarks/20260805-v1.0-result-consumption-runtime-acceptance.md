# DuckDB Result Consumption Runtime Acceptance

> Status: passed for the v1.0 Slice E acceptance gate
> Date: 2026-08-05

## Scope

This report closes the final runtime acceptance for the queryable result
contract. It exercises the accepted eggNOG-mapper and InterPro/Pfam runtimes
through named profiles, with both the local SQLite/POSIX Store and the shared
PostgreSQL/HTTP Store. It also verifies that a workflow consumer can receive
one result file and query it without importing SeqEvi.

The probe used one deterministic protein that was not already present in the
shared Store:

```text

Length:     222

```

`/home/fqzhang/tmp/seqevi-slice-e.3MHRuc`. Raw DuckDB files and command logs
remain outside the repository; this report records their stable identities and

## External Workflow Consumer Smoke

The shared eggNOG cold result was copied to
`external-consumer/received.duckdb`. A standalone Python process with only the
DuckDB client (no `seqevi` import) successfully ran:

```sql
SELECT InputID, SequenceID, EvidenceStatus, Preferred_name
FROM main.annotations;
```

It returned one hit with `Preferred_name=SYCP3`. The same process read
`_seqevi.metadata` and `_seqevi.column_info`, confirmed
`ResultFormatVersion=seqevi-duckdb/1` and `ResultSchemaID=eggnog-mapper/2`,
and discovered the `SequenceID` and `Preferred_name` columns by catalog query.
The received file SHA-256 was
`946f5e96397f2964b63a75b16bdbe53625c7f1d5f1a9428698d6471ae7e31092`.

An initial attempt with the host `python3` failed because that interpreter did
not have the DuckDB client installed. This is an environment packaging note,
not a result-contract failure; the supported SeqEvi virtual environment and a
normal DuckDB-enabled workflow image both satisfy the consumer boundary.

## Decision

Slice E is accepted. The local and shared Store paths produce the same
adapter-native scientific values, cache reuse is visible in `run_metrics`, the
single DuckDB file is self-describing, and an external workflow can consume
`main.annotations` without SeqEvi-specific code. The remaining managed
onboarding work is tracked separately and is not implied by this acceptance.
