## Blockers And Decision

the explicit prior-validation candidates and in a bounded lookup of
`/home/fqzhang/tmp` and `/tmp` (maximum depth four, exact documented size
24,038 bytes). Therefore the documented input SHA-256
`2f408a5a71f7b8e03f7274e424dde51c5b8cabb438c93585277fc846dab45287`
could not be reproduced.

The release image was not cached. A temporary development image also could not
be built under the accepted rule because the Dockerfile's exact pinned base
`python:3.13.11-slim-bookworm@sha256:ac76900038d8606cc99b413d4ede77bc7152f1e42b94cf5d50d4b80a999652fe`
was not cached. Registry pull and push were outside this gate. The nearby
untagged images were service images with `seqevi serve` entrypoints, not the
dbCAN runtime.

No deterministic substitute was run: it could not exercise managed-v2 without
an accepted runtime image, and it would not pass the public gate. Consequently
no local-v1, managed-v2, or later-process replay result was produced, and none
of the requested scientific equality claims is accepted. The residual gate
requires the documented 50-record input and an already cached release image, or
the exact pinned base made available for a temporary development-only build.
