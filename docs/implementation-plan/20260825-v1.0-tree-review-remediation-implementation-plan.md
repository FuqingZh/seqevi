pending; not runtime authority

## Goal

Close the confirmed defects and documentation-authority gaps recorded in the
corrected 0.3.5 tree review without changing evidence identity, adapter-native
schemas, Store reuse rules, released compatibility, or incomplete acceptance
records.

This plan records delivery order. It is not runtime authority. Approved
architecture documents remain authoritative until a later versioned successor
updates them.

## Authority And Compatibility Baseline

- Repository guidance: `AGENTS.md`.
- Documentation entrypoint: `docs/README.md`.
- Current scientific contracts remain the highest versioned documents listed
  as current in `docs/README.md`: evidence v1.6, adapter v1.3, result v1.1,
  profile v1 plus managed v2.2, storage v1.6, progress v1.1.
- The tree review is observational. It does not enter the architecture
  authority order.

A successor that changes public contracts must update the authoritative
document and its focused tests together. A successor that only repairs
implementation against an existing contract does not create a new architecture
version.

## Non-Goals

This plan does not authorize:

- managed eggNOG or InterPro onboarding;
- repeating Slice D as a pass, or converting the deferred GHCR pull into
  passing evidence;
- representing D5 as available before a claim-before-OCI path exists;
- InterPro target-Store sanity or later seeding gates;
- global cache-seeding corpus expansion;
- public progress protocols, ETA, or multi-input scheduling;
- a plugin framework or a universal annotation table;
- coupling Docker into the scientific domain model.

   across `docker rm`. If publication already succeeded, cleanup failure must

### Unit 2 — Reliability and bounded parser hardening

Repair the confirmed local-sweeper and Docker mount-parser gaps without
changing immutable evidence bytes or released Store behavior.

1. Local claim sweeper logs and continues after non-busy operational errors,
   matching the PostgreSQL service sweeper.
2. Reject Docker `--mount` separator characters in source paths, or use a
   non-CSV bind form.
3. Add a direct legacy-commit/ClaimSession race regression for SQLite and
   PostgreSQL that preserves both accepted winner orders and immutable
   conflicts. Do not reject legacy commit against a live claim.

Validation: focused local-Store and OCI tests; PostgreSQL and SQLite for the
compatibility regression; `pdm run check`.

### Unit 3 — Product decisions, refactoring, and leftovers

1. Optional shared-Store service token, or refuse `--host 0.0.0.0` without an
   explicit flag (C-3).
2. Decide whether SeqEvi needs a distinct whole-invocation deadline. Preserve
   the existing meaning of `--timeout-seconds` as external-tool timeout unless
   a public successor contract changes it; document peer wait as lease-driven.
3. Decide whether shared-Store OCI needs egress narrower than Docker bridge.
   Current bridge behavior conforms to the managed-distribution contract.
4. Drop unused claim-transport constants and Slice A prototype helper naming.
   Rename `AnnotationSummary.output_dir` only with an explicit compatibility
   decision.
5. Split `src/seqevi/annotate.py` into lookup, tool batch, busy-wait, and
   publish helpers so the main path is shallow again (`AGENTS.md`).
6. Kit manifest versus hardcoded OCI paths: either implement the documented
   kit fields or amend managed-distribution architecture to the literals that
   0.3.5 actually ships.
7. Fetch-batch metrics: stop hard-coding `store_fetch_batches` to 1 if the
   orchestrator still advertises batch counts.

Validation is selected for the accepted Unit 3 slice. Decisions and
documentation use their focused checks; runtime or public-contract changes use
focused tests plus `pdm run check`. A kit-contract amendment is a new
architecture version; a code-only kit-field addition is not.

## Stop Rules

- Unit 0 closure does not authorize Units 1-3, managed eggNOG or InterPro
  onboarding, release, or runtime work; each remains separately pending until
  its own authority and validation obligations are satisfied.
- Do not start D5 work unless concurrent managed writers on a shared Store are
  an accepted product promise. Until then, document single-writer-per-key for
  managed dbCAN.
- Do not repeat expensive adapter acceptance when ToolRuntimeDigest,
  ResourceID, semantic parameters, harness, and input lineage are unchanged.
- Do not merge a unit that leaves README and the CLI command surface in
  contradiction.

## Validation Gate

Apply the current
[validation strategy](../testing/20260825-v1.4-validation-strategy.md) to each
unit. Runtime and compatibility units require repository-owned
`pdm run check`; shared-Store behavior changes additionally require PostgreSQL
17 and SQLite. Documentation-only cleanup uses documentation consistency,
relative-link, diff, and directly affected contract checks. Contract changes
require the authoritative architecture document and focused tests in the same
change.
