## Authority And Delta Scope

This narrow successor controls only the remaining InterPro/Pfam target-Store
lane. The eggNOG sanity/C1/C2 qualification lane and scoped dbCAN gate are
already closed by their
[eggNOG](../benchmarks/20260818-v1.0-eggnog-target-store-closeout.md) and
[dbCAN](../benchmarks/20260819-v1.0-dbcan-target-store-closeout.md) records;
neither qualification is a prerequisite to repeat. eggNOG is historical
accepted evidence and its eventual corpus expansion remains a separate global
program-completion fact; it is not an execution predecessor for any InterPro
gate. This successor explicitly supersedes the master plan's cross-adapter
ordering for this lane. Its current authorization ends after serial sanity and
independent replay. C1, C2 and E1-E6 are not authorized by this document or its
v3 evidence; they require the accepted sanity evidence and a later successor.
All other master-plan input, backup/export, capacity, Store/CAS reconciliation,
immutable-forward recovery, output, retention, and global stop rules remain in
force unless this document states an InterPro-specific delta.

For this InterPro lane, the master plan's `no other seeding writer`
predecessors and whole-Store/CAS equality or global-delta stop conditions are
superseded: unrelated writers may continue, while acceptance and stop decisions
are scoped to exact `K`, its referenced artifacts, native ClaimSession outcomes,
and capacity reserves. Global health, schema, backup/export, integrity,
capacity and final-reserve safeguards remain mandatory; global counts, bytes
and inventories are observational production context rather than attribution.

The execution identity is the released `seqevi==0.3.1` distribution and named
`interpro-pfam-38.1` profile. Preflight must resolve and freeze the profile's
actual adapter contract, ToolRuntimeDigest, ResourceID, canonical semantic
parameters and InterProScan/Pfam/JDK runtime components. Historical expected
identities are the accepted InterProScan 5.77-108.0,
Pfam 38.1 runtime digest
`sha256:108b8fb3735c166fd30c3a5189240b40acee66f3200107b2967cd16728afefd4`
and ResourceID
`interpro/108.0/pfam/38.1/sha256:ffdda753ae10b2942abab6e364dcc2a8ab16d3df1ff9f382692ec4d367a64860`.
Any mismatch stops Preflight; it is not silently refreshed.

For this direct host profile, immutability is the approved cryptographic
identity contract, not a Unix permission contract. The approved v1 execution
profile and adapter contracts require strict resolved paths, immutable runtime
and ResourceID checks, but do not require an OS-level read-only mount. The
released `seqevi resource verify` command performs the full content hash of
`pfam_a.hmm` and `pfam_a.dat`; ordinary adapter construction does not replace
that audit. Its ToolRuntimeDigest covers the selected Java, launcher, JAR,
HMMER components and normalized properties. The managed-v2 read-only
mount requirement is dbCAN-specific and does not govern direct InterPro.
Preflight and sanity refresh therefore require the released full `seqevi
resource verify`, no SeqEvi write to the caller-owned source resource tree, and
identical bounded before/after resource-tree identity readback. For sanity,
create a task-specific CephFS metadata snapshot under the exact resource
root's `.snap`, freeze its identity, and use `bwrap` to bind that snapshot
read-only onto the same absolute resource path for the entire annotate and
replay process trees. Run full released resource verification inside that
overlay before execution and require identical source, snapshot and
inside-overlay readback after replay. A writable source mount alone is not a
stop because the gate reads only the immutable snapshot; missing or drifting
snapshot/overlay verification is.

Affected repository documents are this successor, the documentation index,
the master plan's continuation pointer, and—only after a gate passes—a dated,
sanitized benchmark record. Raw evidence stays outside the repository under a
fresh `/home/fqzhang/tmp/seqevi-seed-<run-id>`.

## Fixed Reuse And Prohibitions

Execution reuses released SeqEvi boundaries rather than reproducing them:

- `stage_fasta` supplies canonical validation, InputID handling, SequenceID
  identity and the staged input digest; FASTA is never hand-parsed.
- The resolved `AdapterContract.evidence_key` constructs every target
  EvidenceKey; identities are never hand-constructed.
- Released Store `lookup_many` and artifact fetch APIs perform bounded,
  read-only inventory and payload checks; existing PostgreSQL/CAS audit logic
  supplies schema, row/count/digest, reference, residue and filesystem
  reconciliation. Every gate's raw evidence freezes the SHA-256 of every audit
  harness file actually used, the complete SQL text and bound parameters or
  command argument arrays, and the released SeqEvi package/version. Prior audit
  evidence is reusable only when that complete implementation identity is
  unchanged and revalidated; an unspecified host-retained script is not
  accepted lineage.
- Any later authorized execution uses `seqevi annotate --json`; result
  validation uses `scan_annotations`, `sha256_file`, DuckDB queries and Polars
  expressions against the adapter-native result schema.
- The accepted [containment harness
  record](../benchmarks/20260819-v1.0-interpro-preflight-containment-harness-acceptance.md)
  and its exact source lineage are reused. Preflight freezes a finite InterPro
  internal `--timeout-seconds` and a strictly longer external watchdog; it
  cannot inherit eggNOG's numeric deadlines or weaken the accepted cleanup.

This successor explicitly prohibits product API, adapter contract, evidence
identity or Store schema changes; a generic or resumable seeding runner; a new
scheduler or dependency; copied per-gate runners; private contention hooks;
manual Store/CAS writes; new locks or maintenance windows; production pauses;
and merging adapter-native Pfam output into another annotation schema. Host
paths and the evidence root remain operator evidence, not product configuration
or domain-model contracts. This corrects only the execution-plan audit method;
it preserves the approved architecture and requires no new authoritative
architecture document.

## Read-Only Preflight

Fresh read-only Preflight v3 is accepted; delivery-gated serial sanity and its
independent replay are the only active slices. Production workloads may
continue throughout sanity. C1, C2 and E1-E6 are deferred and unauthorized.
The Preflight harness itself
performs no annotation, ClaimSession open/acquire/finalize, Store commit, CAS
upload, profile publication, resource mutation or Store maintenance. Its
mechanically reviewable call boundary is limited to released `stage_fasta`,
`AdapterContract.evidence_key`, `EvidenceStore.lookup_many`/`fetch_many`,
read-only profile/resource verification, short read-only PostgreSQL consistent
snapshots, filesystem capacity reads and native DuckDB/Polars/audit reads.
Acceptance proves self-nonmutation from that boundary and read-only SQL; it
never infers self-nonmutation from equality of global Store state.

Using bounded, non-recursive discovery from the accepted corpus and host
evidence, it must:

1. Freeze the intended 50-file corpus as a sorted manifest with exact path,
   size, file SHA-256, record and unique SequenceID counts, and sorted
   SequenceID-set digests. Use `stage_fasta`; aggregate agreement with the old
   planning snapshot is a check, not proof of byte continuity.
2. Record the exact released SeqEvi package/source identity and resolve
   `interpro-pfam-38.1`. Freeze the accepted profile, runtime, resource and
   semantic identity, including the installed distribution digest and its
   corresponding source commit/blob identity; a version string alone is not
   sufficient. Verify the resource lock against the exact components,
   freeze a bounded before snapshot of the resource and runtime components,
   and require an identical after snapshot. Record that SeqEvi performs no
   source-tree write; do not treat Unix writability by itself as drift.
3. Freeze fresh target `/health`, capabilities, schema revision and the
   service/database/artifact-root mapping. Record global PostgreSQL counts,
   database size, ClaimSession counts and CAS bytes only as production trend
   and capacity context. Unrelated global growth is allowed and is not an
   attribution or acceptance gate. Record the applicable historical
   export/readback precondition; stop if the Store has become production
   authority without the master plan's completed identity-bearing backup.
4. Record PostgreSQL, CAS filesystem and project/output-root availability,
   memory/CPU and relevant scratch/I/O baselines. Freeze operator-approved
   minimum final reserves for PostgreSQL, CAS, project/output space and memory;
   Preflight records availability but makes no growth or concurrency claim.
   Derive the production margin from a representative duration/load or an
   independently accepted worst-case bound; zero growth during the short S0/S1
   interval is not a future-gate bound.
5. Freeze exact sanity, C1-A, C1-B, C2-BLF and C2-UniProt inputs from the
   manifest. Prove the master-plan disjointness rules and the C2 9,115-key
   subset/9,116-key union relationship with canonical SequenceID sets.
6. Derive and freeze each exact target key set `K` with the resolved
   `AdapterContract.evidence_key`. Each authoritative K snapshot is a short
   PostgreSQL `REPEATABLE READ, READ ONLY` audit keyed by all five EvidenceKey
   coordinates: SequenceID, adapter contract version, ToolRuntimeDigest,
   ResourceID and semantic-parameter hash. Take S0, cross-check the same keys
   and referenced artifacts with bounded released `lookup_many`/`fetch_many`,
   then take S1. Public Store lookup is not itself the consistent snapshot.
   Freeze present/missing counts and set digests plus immutable payload and
   referenced-artifact identities in each snapshot. Validate only artifacts
   referenced by `S0 union S1`; do not require a full CAS inventory or full
   database dump.
7. Classify every key transition. Accept `missing -> missing`,
   `missing -> present` as concurrent forward progress, and
   `present -> same-present`. Fail `present -> missing`, changed immutable
   payload or artifact identity, corrupt/missing referenced artifacts,
   unclassifiable target state, schema/resource identity drift, health failure
   or insufficient capacity. The resulting all-missing, all-present or partial
   branch is based on S1. If a selected key advances while public reads are in
   progress, take a fresh scoped snapshot and reclassify instead of claiming a
   stable mixed branch; `missing -> present` remains allowed forward progress.
8. Record only native ClaimSession claims whose EvidenceKeys intersect `K` in
   each short snapshot. Global ClaimSessions are allowed. An intersecting
   claim is refreshed and resolved through the native ClaimSession protocol
   immediately before mutation; overlap alone does not fail Preflight and no
   private hook or external lock is introduced.
9. Freeze a finite InterPro internal timeout from accepted runtime evidence and
   the exact sanity input bound, an external fail-closed operator cutoff,
   cleanup grace,
   containment command lineage and empty-boundary checks. Because the internal
   timeout applies to the one sanity adapter batch. Freeze 14,760 seconds as a
   fail-closed operator cutoff plus a separate 60-second termination grace;
   this is not a claim that all healthy invocations complete within that bound.
   Any timeout, unexpected foreign intersecting claim or unclassifiable state
   fails sanity. C1/C2/expansion overhead and concurrency bounds are deferred.
10. Freeze isolated project, DuckDB, log and JSON paths for sanity and replay;
   prove none aliases another, the Store artifact root or the resource tree.
11. Record in raw evidence the actual Store/CAS audit harness file SHA-256
   values, complete read-only SQL text with bound parameters or complete
   command argument arrays, and released SeqEvi package/version. Validate this
   lineage at every gate before reusing an audit verdict; any change requires a
   new mechanically reviewed audit identity and stops reuse of predecessor
   evidence. This lineage requirement does not add a runner, API or schema.

Preflight passes only when all scoped readbacks are authoritative,
digest-recorded and classifiable under the S0/S1 transition rules. Global
production additions between snapshots are allowed. The evidence must show
the read-only call/SQL boundary, referenced-artifact verification, capacity,
and zero Preflight-owned mutation without relying on global equality. A
sanitized Preflight benchmark may be committed only after that complete
readback; otherwise preserve raw evidence and report the exact gap without
guessing or starting annotation.

## Key-State Branches

The selected branch is refreshed immediately before any later authorized
mutating gate, together with capacity and intersecting native claims:

- **All-missing:** the exact frozen target set may run the gate's
  cold/concurrent shape after its predecessor and capacity gates pass. Expected
  final target state is reconciled over exact `K`; an independent replay then
  proves target integration. Unrelated production growth is not attributed to
  the gate.
- **All-present:** audit every target payload and CAS reference and run
  independent complete-input `annotate --json` replays; require every key
  cached and zero computation. Reconcile exact `K` and its referenced
  artifacts without requiring zero coordination-table, total PostgreSQL or
  global CAS growth. Keep that
  target replay-only truth distinct, then use a fresh isolated HTTP Store
  backed by isolated PostgreSQL and POSIX artifacts, matching the target
  deployment's released shared-Store behavior, with the identical released
  code, harness, inputs, ToolRuntimeDigest, ResourceID and semantic parameters
  for InterPro sanity cold/replay evidence. A local path/`LocalStore` cannot
  qualify the shared-Store mechanism. Fresh evidence
  cannot claim target mutation, capacity or contention.
- **Partial:** digest disjoint present and missing subsets, validate/fetch the
  present payloads, and run the unchanged complete sanity input so only the
  frozen missing union computes. Then require independent zero-compute replay.
  Do not label the target result cold or delete target cache.

No branch deletes accepted evidence to manufacture misses. A legitimate
partial state is forward progress; unknown or drifting state is a stop.

## Gate Graph And Acceptance

```text
read-only Preflight
  -> target payload/CAS proof plus selected-branch sanity/replay
  -> fresh isolated sanity cold/replay when target sizing is insufficient
  -> stop for accepted sanity evidence and a later successor
```

Sanity inherits the master plan's exact-input,
one-adapter-family boundary, fresh identity/health/key-state/capacity checks,
isolated projects and adapter-native DuckDB/JSON validation. Every output is
opened read-only with `scan_annotations`, checked by DuckDB/Polars for schema,
tables, input map, hit/no-hit and row cardinalities, and hashed with
`sha256_file`. Target execution reconciles exact `K`, `annotate --json`
computed/cache metrics, final immutable payloads, referenced artifacts and
native ClaimSession outcomes. It does not claim all global Store/CAS growth;
unrelated production activity remains context. Capacity uses the minimum free
space observed across scoped snapshots, the frozen final reserve and a
conservative production-growth margin. Exact target state, intersecting claims
and capacity are refreshed immediately before sanity. Any controlled fresh
isolated-Store sanity evidence remains a separate physical Store and execution
identity.

Artifact acceptance proves the immutable winning references for exact target
`K` and records every artifact digest, size and path proposed or uploaded by
the gate invocation. If native `finalize_many` reports `EXISTING`, reconcile
any invocation-uploaded object that is not a winning evidence reference as
valid invocation-owned CAS growth: verify its content identity, include its
bytes in capacity/residue accounting and retain its lineage. Continue to
exclude unreferenced global CAS objects that cannot be attributed to the
invocation; absence of invocation-owned work residue remains mandatory.

- **Sanity:** use the frozen 2,729-record Lacticaseibacillus input. Before
  launch, freeze representative production MemAvailable variation from bounded
  `/var/log/sa/sa20` and current `sa21` history, retain the operator-approved
  256 GiB final reserve, and apply a process-tree `MemoryMax` derived from the
  refreshed host capacity without consuming that reserve. Continuously monitor
  the reserve; crossing it terminates the owned process tree and fails the
  gate. Record actual whole-process peak memory for a later concurrency plan.
  Run annotate and replay only through the official-wheel isolated environment
  and the same-path read-only resource snapshot overlay described above. An
  all-missing or sufficient partial target result supplies measured InterPro
  growth, retained output and peak-scratch rates; all-present supplies target
  payload/CAS and replay acceptance only. Those mechanism rates and measured
  memory are evidence only; they authorize no later gate.
- **Deferred gates:** C1, C2 and E1-E6 are not current gates. Their prior
  descriptions, concurrency assumptions, 300-second overhead allowance,
  production-memory budget and large cached-replay requirement are withdrawn
  from this successor's authorization. A later successor must start from
  accepted sanity evidence and independently resolve those bounds.

An all-present target sanity branch cannot invent cold sizing. Its target
proof/replay is combined only at
the acceptance-matrix level with separately identified fresh isolated-Store
mechanism evidence; neither physical Store's facts are relabeled as the
other's. Stop only when the required target integration or fresh mechanism
layer remains unproved.

## Stop, Cleanup And Recovery

Stop and preserve evidence on package, source, profile, ToolRuntimeDigest,
ResourceID, semantic, input, EvidenceKey, schema or containment-lineage drift;
failed health/backup boundary; timeout; non-empty owned process boundary;
DuckDB/JSON or input-map defect; HTTP/commit error; an unclassifiable scoped
S0/S1 transition; `present -> missing`; changed immutable payload/artifact
identity; missing/corrupt referenced artifact; upload residue attributable to
the gate; payload inequality; or loss of capacity after applying minimum
observed free space, frozen reserve and conservative production margin.
Unrelated global Store, ClaimSession, database or CAS growth is not a stop.

On internal timeout, allow the accepted SeqEvi `ToolRunner` path to terminate
and reap its adapter group. On outer-watchdog expiry, propagate termination
through the accepted bridge, apply the frozen bounded TERM/KILL cleanup, and
prove both nested and outer owned boundaries empty. Preserve primary and
cleanup errors distinctly. Remove only invocation-owned temporary material
after audit; never delete immutable Store rows or CAS artifacts, overwrite a
result, or retry an external write with unknown outcome before authoritative
readback proves the intended state absent.

Raw evidence remains under the run root. Only small sanitized manifests,
summaries and audit outputs may enter a dated benchmark record after a gate is
accepted; credentials, raw environments, unredacted service/database
configuration and private host topology stay excluded.

## Compact Delivery Splits

1. **Plan and read-only Preflight:** this successor/index/master pointer, full
   local gate, then a separately committed sanitized Preflight benchmark only
   if every authoritative readback passes.
2. **Sanity-only closeout:** one final review unit for serial sanity and its
   zero-compute replay, including snapshot-overlay identity, memory/capacity,
   native result, Store/CAS, ClaimSession, containment and cleanup evidence.
   C1/C2/E1-E6 require a later successor and are not part of this delivery.

Each split runs `pdm run check`, receives exact-current-head normal review and
retains zero unresolved threads before merge eligibility. No split changes the
product contract or folds closed eggNOG/dbCAN work back into the active lane.
