# Shared Store Cache-Seeding Implementation Plan

Version: v1.0
Date: 2026-08-07
Status: approved execution plan; execution not started
Target release: SeqEvi 0.2.0
Issue: #22

## Goal

Safely seed the existing PostgreSQL and POSIX-artifact shared Store from the
measured FASTA corpus with released `seqevi==0.2.0`. Execution advances through
small, auditable scale gates, preserves adapter-native schemas in independent
DuckDB results, and records machine-readable JSON summaries. The plan first
proves concurrent Store behavior, then expands only while identity, capacity,
health, output, and replay gates remain satisfied.

This is an approved plan for later execution, not evidence that seeding has
run or that any gate has passed.

## Non-Goals

- changing a product API, Store schema, evidence identity, or adapter contract;
- creating a universal annotation table or merging eggNOG and Pfam schemas;
- writing Store database rows or artifact files by hand;
- immediately running every file or every adapter;
- downloading, copying, redistributing, or taking ownership of caller-managed
  annotation resources;
- coupling SeqEvi to a FASTA source system, project model, workflow scheduler,
  container engine, or host filesystem layout; or
- building a resumable seeding runner in the first execution.

Host paths are execution parameters, not SeqEvi product contracts. Accepted
run summaries move to a `seed-runs` directory that is a sibling of the Store's
`artifacts` directory. Execution never writes summaries or other manual files
inside `artifacts`.

## Measured Starting State

### Input snapshot

The planning snapshot contains 50 FASTA files and 2,367,598 records. Parsing
each record through SeqEvi's released canonical sequence rules produced
2,102,183 unique canonical sequences and 265,415 duplicate occurrences
(`total records - unique canonical sequences`, 11.21% of records). The scan
found no invalid sequences, empty InputIDs, or duplicate InputIDs.

The measurement method is: enumerate the bounded corpus file list; parse every
FASTA record; validate a non-empty, corpus-unique InputID; canonicalize and
validate the sequence with the released SeqEvi identity implementation; count
records; count distinct resulting SequenceIDs across all files; and derive
duplicate occurrences from the difference. Before execution, repeat that scan
and create a sorted manifest containing relative path, byte size, record count,
unique SequenceID count, a digest of the sorted per-file SequenceID set, and
streaming file SHA-256 for every file. Retain the sorted SequenceID sets for
inputs whose overlap is an execution gate. Record the measurement command or
script identity and `seqevi==0.2.0` version with the manifest. Any count,
validation result, membership, or digest difference is input drift and stops
the run pending review; the numbers above are not a substitute for that
refresh.

## Existing Safety Invariants

No code change is required for the first gates. On `origin/main` at
`930c0ae5638d9b700b3f5f36ad098b183ff1caf6` (the 0.2.0 release), PostgreSQL
uses a composite evidence primary key over SequenceID, adapter contract
version, ToolRuntimeDigest, ResourceID, and semantic-parameters hash. Artifact
digests are primary keys. Inserts use `ON CONFLICT DO NOTHING`; a losing writer
then reads the stored row and verifies immutable semantic parameters, status,
and payload digest. A different payload for the same key fails with an
integrity conflict. It is never last-writer-wins.

The POSIX content-addressed store streams into a same-directory temporary file,
checks expected byte size and SHA-256, flushes and `fsync`s the file, and
publishes with an atomic hard link. A concurrent publisher verifies the already
published digest. The containing directory is `fsync`ed after publication, and
temporary files are removed in cleanup. Artifact uploads precede the evidence
commit, however, and equal scientific payloads may have different valid
artifact encodings. A losing writer can therefore leave a valid, unreferenced
CAS artifact. Accepted contention must reconcile evidence-referenced artifacts
separately from all uploaded artifact rows/files, account for both categories
in capacity, require one path for each individual digest, and find no
`.seqevi-upload-*` or `.seqevi-artifact-*` temporary residue. It must not claim
one artifact digest per scientific payload.

These invariants explain the expected outcome; the concurrency gate must still
exercise and measure the deployed PostgreSQL/artifact Store rather than infer a
pass from source inspection.

## Evidence Contract

Each process writes only beneath its own project root. Preserve, for every
slice:

- refreshed input-manifest identity and selected file digests;
- exact package version, command argument array, start/end time, exit code,
  wall time, peak RSS, CPU and I/O observations;
- adapter, ResourceID, ToolRuntimeDigest, adapter contract version, and
  canonical semantic parameters;
- computed/cache/no-hit counts and any HTTP status or retry observation;
- Store health plus before/after sequence, evidence, artifact, artifact-byte,
  and PostgreSQL-byte values;
- DuckDB file digest, schema identifiers, tables, row counts, input-map counts,
  and focused content checks;
- evidence-referenced artifact digests, all newly uploaded artifact digests,
  valid unreferenced losing-writer uploads, their respective byte totals,
  per-digest row/file reconciliation, and temporary-residue scan; and
- a JSON summary with the same acceptance decision and stop reason as the
  human-readable run summary.

Evidence is first written beneath
`/home/fqzhang/tmp/seqevi-seed-<run-id>`. After a gate is accepted, copy only
its sanitized manifest, summary, and small audit outputs to the Store sibling
`seed-runs/<run-id>/`. Retain every accepted DuckDB result in its declared
project root through final reconciliation; only after final completion may the
operator's longer-term retention policy remove or archive it. Never record
credentials, raw environment dumps, or unredacted service configuration.

Future durable scale and performance claims belong in a versioned document
under `docs/benchmarks/`; an execution that changes a reusable operational
procedure must update or add the appropriate document under `docs/operations/`.
Those later records contain measured results and exact environment evidence;
this plan does not invent them.

## Preflight Slice

**Predecessors:** released `seqevi==0.2.0`; access to the corpus, named
profiles, read-only resources, Store, backup mechanism, PostgreSQL readback,
and artifact filesystem; no other seeding writer.

**Invariants and local non-goals:** this slice is read-only with respect to the
Store and performs no annotation or manual Store write; do not refresh a
profile or resource identity silently; do not infer capacity sufficiency from
filesystem free space alone.

**Actions and outputs:**

1. Refresh the SHA-256 input manifest with the measurement method above.
2. Run `uvx --from seqevi==0.2.0 seqevi --version` and a harmless prewarm so
   package acquisition is outside timed gates; retain resolver/version output.
3. Validate `eggnog-5.0.2` and `interpro-pfam-38.1`; record ResourceID,
   ToolRuntimeDigest, semantic defaults, and read-only mount evidence.
4. Read Store health and baseline counts. Trigger the existing coordinated
   PostgreSQL/artifact backup, read back its completion state and identities,
   and retain the supported backup reference. Do not advance on trigger success
   alone.
5. Read current PostgreSQL and artifact-filesystem capacity through supported
   host tools and record the available-byte baselines. Treat these values as
   availability inputs only; the serial sanity slice supplies measured growth
   before any 2x projection is accepted. Freeze an operator-approved minimum
   final reserve, expressed separately in PostgreSQL and artifact-filesystem
   bytes, before the first mutating slice.
6. Recompute and retain the sorted SequenceID sets for
   `Trichoderma_reesei_BLF.fasta` and its UniProt FASTA, prove the 9,115 set is
   a subset of the 9,116 set and their union has 9,116 members, and query the
   frozen eggNOG and InterPro-Pfam identities to prove all of those EvidenceKeys
   are missing. Reserve those exact adapter-specific EvidenceKeys for C2; every
   mutating slice before that adapter's C2 must exclude them.
7. Create independent `project-a` and `project-b` roots, result paths, logs,
   and JSON-summary paths. Verify neither output path aliases the other or the
   Store artifact root.

**Focused verification and acceptance:** refreshed snapshot matches; health is
`ok`; backup readback is complete and identifies a coordinated restorable
boundary; profiles resolve to frozen identities; capacity availability is
recorded without a growth claim; the minimum final reserve is frozen; the C2
sets, relationship, missing state, and reservation are retained; output roots
are independent.

**Stop, cleanup, and rollback:** stop on any drift, failed backup readback,
identity mismatch, invalid profile/resource, output alias, or inadequate
capacity availability. Preserve evidence; never delete Store rows or artifacts
to simulate rollback. Because this slice is read-only, any unexpected Store
delta is itself a stop condition.

## Serial Sanity And Sizing Slice

The execution graph is fixed:

```text
read-only Preflight
  -> eggNOG sanity -> eggNOG C1 -> eggNOG C2
  -> InterPro-Pfam sanity -> InterPro-Pfam C1 -> InterPro-Pfam C2
  -> E1 -> E2 -> E3 -> E4 -> E5 -> E6
```

Run this slice first for eggNOG. After eggNOG sanity, C1, and C2 all pass, run
it for InterPro-Pfam before that adapter's C1 and C2. This preserves one adapter
family at a time and keeps the complete eggNOG concurrency lane ahead of
InterPro-Pfam.

Use the 2,729-record Lacticaseibacillus input for one serial cold run followed
by an independent replay. The input must be disjoint from the C2 reserved
SequenceID set for the active adapter identity.

**Predecessors:** accepted read-only Preflight; fresh backup and Store-health
readback; frozen profile/resource/semantic identity; verified C2 reservation;
authoritative lookup confirms every manifest-derived sanity EvidenceKey is
missing for the active adapter identity; no other seeding writer.

**Invariants and local non-goals:** one process and one adapter family; no
concurrency claim; no C2 reserved EvidenceKey; isolated cold and replay project
roots; no manual Store write.

**Outputs:** cold and replay DuckDB/JSON results; selected input-set identity;
computed/cache/no-hit counts; full Store before/after/replay baselines;
referenced and unreferenced artifact reconciliation; latency and resource use;
bytes-per-1,000-unique-EvidenceKeys calculation; next-slice projection.

**Focused verification:** the cold run exits zero and produces a complete,
schema-correct result; Store evidence growth equals the cold run's missing-key
set; the independent replay reports one cache hit for every manifest-derived
unique EvidenceKey and zero computed records and has a complete output.
Calculate PostgreSQL growth and total artifact growth, including valid
unreferenced uploads, per 1,000 newly stored unique EvidenceKeys. Use those
measured rates and the next slice's missing-key upper bound to require at least
2x projected headroom in both storage domains.

**Acceptance:** outputs and identities reconcile; replay is zero-compute; the
artifact audit reconciles every new row/file and reference; no upload temp
residue exists; measured 2x headroom is sufficient for C1. Acceptance for one
adapter does not supply a growth rate or capacity decision for another.

**Stop, cleanup, and rollback:** stop on any global condition, any C2
reservation overlap, or inability to establish measured 2x headroom. Preserve
both DuckDB outputs and immutable Store state. Refresh the baseline before any
reviewed retry; do not delete valid cache entries or unreferenced CAS uploads.

## Concurrency Qualification

Concurrency qualification runs eggNOG first. InterPro-Pfam begins only after
all eggNOG concurrency and replay criteria pass. Use 8 adapter threads per
process initially; use the declared 4-thread InterPro fallback only when the
reason and resource evidence are recorded. Run one adapter family at a time.

### Slice C1: Disjoint concurrent writes

**Predecessors:** accepted serial sanity and measured 2x headroom for the same
adapter family. For InterPro-Pfam, eggNOG C2 must also be accepted.

**Invariants and local non-goals:** two independent processes, projects, and
outputs; disjoint input SequenceIDs that exclude all C2 reserved keys;
identical adapter/profile/resource and semantic parameters; no attempt yet to
prove same-key contention.

**Outputs:** two DuckDB files, two process JSON summaries, synchronized Store
before/after evidence, resource-use capture, artifact audit, and one combined
gate summary.

**Focused verification:** both processes exit zero; no HTTP 409/422/5xx,
deadlock, commit error, identity drift, or schema/input-map mismatch; Store
evidence delta equals the union of missing EvidenceKeys rather than an
unexplained count; both DuckDB results are complete and isolated; committed
payloads are immutable; all new artifact rows/files and evidence references
reconcile, valid unreferenced uploads are counted, each digest has one CAS
file, and no upload temporary file remains. Apply the adapter-specific sanity
growth rates to C2's missing-key upper bound and require at least 2x remaining
PostgreSQL and artifact headroom before accepting C1.

**Acceptance:** every check passes for eggNOG, then independently for
InterPro-Pfam. Record latency, throughput, peak resource use, computed/cache
counts, and Store deltas without claiming overlapping-write coverage.

**Stop, cleanup, and rollback:** stop the adapter family on either nonzero
exit, health/commit failure, conflict, deadlock, residue, or output defect.
Preserve both projects and Store state. Do not automatically retry a
non-idempotent external-tool run or delete accepted immutable cache entries.

### Slice C2: Overlapping same-key writes

**Predecessors:** C1 accepted for the same adapter family; fresh health,
backup, identity, input, and measured headroom checks; authoritative readback
confirms every reserved C2 EvidenceKey remains missing.

Use `Trichoderma_reesei_BLF.fasta` (9,116 unique sequences) for `project-a`
and its UniProt FASTA (9,115 unique sequences, a subset) for `project-b`. The
expected union is 9,116 unique SequenceIDs. Before launch, verify those
cardinalities and the subset/union relationship by recomputing the retained
sorted SequenceID sets and comparing their set digests with Preflight.

**Invariants and local non-goals:** both processes use the same
adapter/profile/resource/Store and semantic parameters. Hold both processes at
a launch barrier after Store lookup preparation where the supported client
surface permits, then release them together so both can observe misses and
compete on identical EvidenceKeys. Do not use private test injection or manual
Store writes to manufacture contention.

**Outputs:** both complete DuckDB results and JSON summaries; barrier timing;
per-process computed/cache counts; request/error observations; Store deltas;
payload equality and artifact reconciliation audit; residue scan; combined
contention verdict.

**Focused verification:**

- both processes exit zero, with no 409/422/5xx, deadlock, or commit failure;
- Store evidence growth equals the missing-key union, never the two-job sum;
- every overlapping EvidenceKey resolves to one immutable equal payload;
- every evidence artifact reference resolves; all uploaded rows/files,
  including valid unreferenced losing-writer encodings, reconcile and count
  toward capacity; every individual digest has one CAS path; no upload
  temporary residue remains;
- project outputs are complete, separate, schema-correct, and have the expected
  input-map cardinalities; and
- independent later processes replay the two inputs with respectively 9,116
  and 9,115 cache hits and zero computed records.

If one initial process sees cache entries before it computes overlapping keys,
record visibility/race coverage but do not claim same-key commit contention was
exercised. Preserve the visibility-only result and stop qualification; do not
delete immutable rows or substitute a different input pair for the frozen C2
contract.

**Acceptance:** eggNOG passes the complete gate, including independent replay,
before the same gate starts for InterPro-Pfam. InterPro-Pfam must meet the same
criteria; a documented reduction to 4 threads per process changes only
execution concurrency, not evidence identity or acceptance. After both adapter
lanes pass, apply their measured rates to E1's missing-key upper bound and
require at least 2x headroom before accepting concurrency qualification.

**Stop, cleanup, and rollback:** stop on replay computed count greater than
zero, identity drift, schema/input-map mismatch, health/commit error, deadlock,
unexplained conflict or delta, payload inequality, artifact residue, or lost
headroom. Preserve all evidence and immutable Store state; do not advance
automatically.

## Expansion Slices

After concurrency qualification, ordinary expansion remains limited to two
files and one adapter family at a time. Each slice repeats fresh health,
identity, manifest, backup-readback, and measured 2x-headroom gates. eggNOG
completes and replays the slice before InterPro-Pfam starts it.

| Slice | Input scope | Predecessor | Scale gate |
| --- | --- | --- | ---: |
| E1 | accepted Lacticaseibacillus sanity, E. coli reference, and accepted C2 Trichoderma inputs | sanity and C2 accepted for both adapters | 16,247 cumulative records |
| E2 | E1 plus Lactobacillus, Pseudomonas, Streptococcus, and Candida | E1 accepted | 101,657 cumulative records |
| E3 | remaining microbial, fungal, and algal inputs | E2 accepted | manifest-derived |
| E4 | UP reference proteomes | E3 accepted | manifest-derived |
| E5 | taxonomy aggregates | E4 accepted | manifest-derived |
| E6 | largest high-overlap inputs | E5 accepted | manifest-derived; last |

For each expansion slice:

**Invariants and local non-goals:** select exact files by refreshed manifest,
never by an unrecorded directory glob; schedule no more than two files; keep
projects and DuckDB outputs isolated; run one adapter family at a time; make no
schema/API change and no manual Store write.

**Outputs:** selected manifest subset; commands and identities; per-file
DuckDB/JSON results; computed/cache/no-hit counts; schema, table, row, and
input-map checks; latency and resource use; Store health and deltas; artifact
audit; replay results; slice acceptance summary.

**Focused verification:** both active processes exit zero; output schemas and
input maps match the adapter contract and selected manifests; Store evidence
delta equals the missing-key union; payload and CAS invariants hold; no temp
residue exists; independent replay has all selected unique keys cached and zero
computed. When a successor exists, measured post-slice capacity must retain 2x
headroom for that successor. For final Slice E6, record remaining measured
capacity and require the minimum final reserve frozen in Preflight instead of
inventing a next-slice projection.

**Acceptance:** all checks pass for eggNOG and then InterPro-Pfam, evidence is
preserved at the declared destination. For E1-E5, the next slice's exact file
list and capacity projection are reviewed; E6 instead accepts the recorded
Preflight-frozen final reserve. Cumulative record counts are selection gates,
not expected evidence-row deltas because canonical duplicates and pre-existing
cache entries are excluded from missing-key unions.

**Stop, cleanup, and rollback:** stop on any global stop condition below.
Terminate no healthy peer merely to hide partial success; preserve each
process's terminal state and evidence. Remove only unneeded caller-owned
temporary outputs after audit and retention decisions. Store rollback is
forward-only: retain valid immutable entries, refresh the baseline, and resume
only through a reviewed later execution.

## Separate dbCAN Gate

dbCAN is not part of the eggNOG/InterPro expansion. Before any large dbCAN
seeding, run the released managed setup dry-run against caller-owned resources
and establish an ordinary reusable profile through the supported setup
surface. The release-equivalent local image is acceptable gate evidence when
it is built from the recorded source revision and release recipe/lock inputs
and its component checksums are verified. Its local image ID or digest need not
equal the published GHCR manifest digest and must never be labeled, recorded,
or presented as that GHCR digest. Hidden test injection is not the default
production surface, and normal operational seeding still requires a supported
reusable profile.

The dbCAN slice has the preflight, concurrency, output, replay, capacity,
evidence, stop, cleanup, and rollback requirements above. It begins with its
own small sanity input and cannot inherit headroom estimates from another
adapter. Large dbCAN seeding requires a separately reviewed selection and
accepted normal profile; this plan does not mark it ready merely because the
Store baseline contains zero dbCAN evidence.

## Global Stop Conditions

Stop the active adapter family, preserve evidence, and do not advance
automatically when any of the following occurs:

- replay computes one or more records;
- ToolRuntimeDigest, ResourceID, profile, semantic parameters, or input digest
  drifts;
- a DuckDB schema, table, row count, or input-map check fails;
- the coordinated backup cannot be read back as complete;
- Store health fails or any upload/commit returns an error;
- a process deadlocks or fails to reach a bounded terminal state;
- an unexplained conflict, Store delta, or payload inequality appears;
- a CAS artifact is missing/duplicated/corrupt or upload temporary residue
  remains; or
- measured capacity provides less than 2x projected headroom for a declared
  successor, or less than the Preflight-frozen final reserve at the last slice.

Recovery begins with an operator-reviewed incident summary, fresh Store and
output readback, and a decision whether the same slice is safe to resume. Never
erase immutable Store state or overwrite evidence to force a clean rerun.

## Final Completion Criteria

Cache seeding is complete only when:

1. the refreshed 50-file manifest accounts for every intended corpus input and
   retains the validated InputID/sequence properties;
2. the serial sanity and sizing slice has accepted cold/replay evidence and
   adapter-specific capacity measurements for eggNOG and InterPro-Pfam;
3. concurrency C1 and C2 have accepted eggNOG and InterPro-Pfam results,
   including demonstrated same-key contention rather than visibility alone;
4. every approved expansion slice has accepted output and zero-compute
   independent replay for both adapter families;
5. final Store rows, referenced and unreferenced artifact digests/bytes,
   health, capacity, and temporary residue have been independently read back
   and reconciled to missing-key unions and all uploaded artifacts;
6. every DuckDB output is present, digest-recorded, schema-correct, and mapped
   to its manifest inputs, with JSON summaries and resource-use evidence;
7. sanitized accepted summaries are retained under the Store sibling
   `seed-runs` area and the final reproducible measurement is published in the
   named future benchmark destination; and
8. failures, exclusions, dbCAN readiness, and unseeded identities are stated
   explicitly rather than converted into success.

Completion is execution evidence to be written later; this document remains
an execution plan until those criteria are actually met.

## Future Automation Decision

The first gates require no repository code change. If repeated execution shows
that interruption recovery or slice bookkeeping needs a resumable runner,
create a separate AO issue and pull request. Its design must be generic and
Store/API-based, preserve the public identity and output contracts, and avoid
Ceph-, corpus-, project-, or host-specific domain coupling.
