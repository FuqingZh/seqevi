## Purpose and observed state

This addendum unfreezes delivery after the approved v1.2 topology encountered
one real merge conflict, limited to `docs/README.md`. The conflict was observed
between authorized `main` at
`96e67b81b333f5339f7075df20f0ed176b60393c` and frozen PR #31 at
`0ba6e155c64d311c77a35ef3f187b99de7a56c31`, whose common base is
`6d43def9d651e262266fa1c4f9f2be340ec73660`. Both sides changed the capability
table and numbered documentation index hunks.

The preserved heads at authorization are:

- `main`: `96e67b81b333f5339f7075df20f0ed176b60393c`;
- PR #31: `0ba6e155c64d311c77a35ef3f187b99de7a56c31`; and
- PR #41: `9f9ca3645b4cd0ca91ef78a13e72c25f86ea6a12`.

PR #31 and PR #41 remain independently owned and unchanged. This addendum does
not authorize a write to either PR, either branch or worktree, either PR body,
or any review thread. In particular, PR #31's product code, tests, CI state,
documentation, exact head, and frozen review evidence remain unchanged.

## Why v1.2 cannot execute unchanged

The v1.2 sequence requires PR #31 to merge unchanged. Git cannot execute that
step against the authorized `main` because the README conflict requires a
resolution commit somewhere. Resolving on PR #31 would violate the frozen-head
contract; resolving during a merge without prior reviewed preparation would
bypass the exact-head documentation, CI, and review gates. The smallest valid
topology therefore prepares `main` in a separate documentation-only unit, then
retries the unchanged PR #31 merge.

1. adds one prominent current-authority pointer before `## Capability Status`,

3. restores numbered-index entries 38, 39, and 40 byte-for-byte to that same

Those restored lines are temporary merge-compatibility text, not current
delivery authority. The prominent pointer declares that v1.2 plus this v1.3
addendum supersede them until PR #31 merges unchanged. No product code, test,
CI configuration, architecture contract, runbook, or frozen-PR evidence changes.

Before delivery, the exact candidate head must be merged with frozen PR #31 in
an isolated temporary repository using:

```text
git merge-tree --write-tree <candidate-head> 0ba6e155c64d311c77a35ef3f187b99de7a56c31
```

The pull-request body records the exact command, candidate head, resulting
merge tree, and exit status. Exit status zero and a produced tree are required.

## Finite delivery and review order

1. Issue #42 opens a ready documentation-only PR from authorized `main` and
   passes `pdm run check` and exact-head CI.
2. The repository automatic GitHub Codex review runs first on that exact head.
   Only in-contract documentation feedback may be handled, and platform
   readback must prove zero unresolved threads. A fix creates a new head and
   restarts this step.
3. The issue #42 owner returns that exact head and settled review state to the
   orchestrator without triggering the designated review. The orchestrator then
   triggers exactly one designated contract-scoped AO final review on the same
   exact head. Its approval is required before merge.
4. The issue #42 owner does not merge the PR. After the issue #42 PR merges
   through separately granted authority,
   platform readback must prove PR #31 remains at
   `0ba6e155c64d311c77a35ef3f187b99de7a56c31` and is conflict-free.
5. The existing PR #31 owner completes only the evidence-thread actions already
   authorized by v1.2, and PR #31 merges unchanged only after every v1.2 gate.
6. PR #41 and all later v1.2 units retain their independent ownership, order,
   acceptance, and stop conditions.

This is a finite compatibility insertion, not a new alternating review loop or
authority transfer.

## Acceptance

Issue #42 is accepted only when all of the following hold on its exact head:

- the diff is documentation-only and limited to this addendum and the exact
  README preparation above;
- PR #31 and PR #41 heads match the preserved values and neither PR was written;
- the common-base README lines compare byte-for-byte;
- isolated `git merge-tree --write-tree` proof with frozen PR #31 exits zero;
- `pdm run check` and required exact-head CI pass;
- automatic GitHub Codex review has settled, all in-contract documentation
  feedback is handled, and zero unresolved issue #42 PR threads remain; and
- after that settlement and zero-thread proof, the orchestrator-triggered
  designated contract-scoped AO final review approves the same exact head; and
- the ready PR closes #42 and records scope, tests, proof, and preserved heads.

No issue #42 acceptance grants merge, product release, or deployment authority.

## Stop conditions

Stop, preserve all observable state, and request a new delivery decision if:

- `main`, PR #31, or PR #41 differs from a preserved head before the issue #42
  branch is established, or PR #31's head changes at any later point;
- the change requires product code, tests, CI, a frozen PR/worktree, a PR #31 or
  PR #41 body, or either PR's review threads to be written;
- the README preparation differs from the exact common-base lines, touches any
  other README content, or fails isolated merge-tree proof;
- automatic review yields out-of-contract work, cannot settle, or leaves an
  unresolved thread, or any acceptance uses a stale head;
- the issue #42 owner triggers the designated AO review, the designated review
  runs before automatic-review settlement and zero-thread proof or against a
  stale head, the correctly ordered orchestrator-triggered final review is
  omitted or does not approve, this issue #42 owner is asked to merge, or
  downstream work proceeds before the compatibility PR merges; or
- any v1.2 compatibility, acceptance, release, or deployment gate would be
  weakened or bypassed.

## Rollback

Before the issue #42 PR merges, rollback is to close only that PR and delete
only its issue-scoped branch; `main`, PR #31, PR #41, their worktrees, and their
evidence remain untouched. After merge but before unchanged PR #31 merges, a
reviewed revert of the issue #42 commit restores the prior README and removes
this addendum if no downstream unit has relied on the preparation. If reliance
exists, publish a new dated addendum rather than rewriting history.

After PR #31 merges unchanged, its README changes naturally replace the
temporary common-base lines. Do not revert PR #31 content or resurrect the
temporary lines as authority. Product rollback remains governed by v1.2 and
does not change code or frozen PR evidence through this documentation unit.
