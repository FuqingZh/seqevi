# Evidence Claim Lease Implementation Plan

Version: v1.0
Date: 2026-08-10
Status: implemented; validation accepted
Target release: post-0.2.0
Issue: #24

## Goal

Add Store-owned, short-lived claims for one complete EvidenceKey so healthy
claim-capable clients normally send each missing sequence to one calculator.
Claims reduce duplicate external-tool work without weakening immutable evidence
correctness. Crash, partition, or lease loss remains at-least-once compute;
SeqEvi does not claim exactly-once execution.

## Fixed Boundary

- A claim covers one full five-coordinate EvidenceKey and its validated
  `semantic_parameters_json`, never a FASTA, batch, project, adapter run, or
  artifact.
- Terminal evidence remains in the existing immutable evidence table. Claims
  live in a separate ephemeral table and are never scientific results.
- Adapter contracts, adapter-native schemas, the annotate CLI and profiles,
  resource identities, Store locations, deployment, and authentication remain
  unchanged. This work adds no Redis, scheduler, plugin, or dependency.
- Existing lookup, fetch, artifact, and commit endpoints remain compatible.
  Old clients keep the released lookup/compute/idempotent-commit behavior.
- Claim-capable clients may fall back to that existing behavior when a service
  does not advertise claim support. Duplicate suppression applies only among
  claim-capable clients using the new surface.

## Lease Contract

The Store chooses a bounded lease duration and reports the expiry and renewal
cadence; callers do not configure either value. Each claim contains the full
EvidenceKey coordinates, canonical semantic JSON, an opaque owner token, a
monotonically increasing generation, `expires_at`, `created_at`, and
`updated_at`.

One atomic batched acquire accepts sequence identities plus EvidenceKeys and
returns exactly one result per request:

- `cached`: immutable terminal evidence already exists;
- `acquired`: the caller owns the returned generation until expiry; or
- `busy`: another unexpired claim owns the key; the response contains only the
  key plus expiry/retry metadata and never exposes owner token or generation.

Acquire is not implemented as client-side lookup followed by claim. Expired
claims may be taken over atomically with a strictly larger generation. Only the
matching owner token and generation may renew, release, or finalize. A stale
generation cannot affect newer ownership. Expiry itself ends authority: even
the same owner token reacquires with generation + 1 after expiry, and expired
claims cannot renew, release, or finalize before another owner arrives.

Renewal continues from acquisition through miss-FASTA creation, adapter work,
commit construction, artifact upload, and every finalization chunk. Normal
failure stops renewal before best-effort release; hard death recovers through
expiry. Release retains an expired generation tombstone so reacquisition always
advances generation and cannot create an ABA credential. Finalization may
delete its claim because terminal evidence prevents reacquisition. A
concurrent terminal record always wins as scientific truth and is reported as
cache reuse to a client that did not compute it locally.

## Interface Shape

Domain values and explicit lease errors live beside existing evidence values
and Store errors. The released `EvidenceStore` protocol remains unchanged;
the additive `ClaimCapableEvidenceStore` protocol supplies acquire, renew,
release, finalize, and capability detection without breaking third-party
structural implementations. Batch calls remain at most 1,000 keys. Adapter
batches remain at most 10,000 identities and contain only keys acquired by
that invocation.

The HTTP service adds strict versioned claim endpoints without modifying the
legacy endpoint schemas. `/health` remains exactly unchanged because released
clients validate it with `extra="forbid"`. A dedicated
`/v1/evidence/claims/capabilities` endpoint advertises claim support and server
lease bounds; HTTP 404 means legacy fallback. The HTTP client validates
response membership, cardinality, owner credentials, generations, and both
client/server batch limits. Lease loss uses HTTP 412 while immutable evidence
conflict retains its released HTTP 409 mapping.
Only `acquired` carries the mutation-authorizing owner token and generation;
busy observations cannot be renewed, released, or finalized by construction.

## Persistence

Alembic revision `0003` creates an ephemeral claim table with the same
five-column evidence primary key, canonical semantic JSON, owner token,
positive generation, expiry, and timestamps. The migration upgrades SQLite and
PostgreSQL from `0002` without changing terminal rows.

SQLite uses a write transaction that serializes acquire decisions under WAL.
PostgreSQL takes sorted unique signed advisory locks for the requested complete
EvidenceKeys, then uses terminal checks, `INSERT ... ON CONFLICT`, and
`SELECT ... FOR UPDATE` inside one transaction to decide cached, acquired,
busy, same-owner renewal, or expired-generation takeover. Transaction-tail
terminal checks and expiry refresh prevent stale returned authority. Renew,
release, and finalize match every key, owner, and generation coordinate in
their modifying statement.

## Annotate Coordination

The main annotate path remains linear:

1. stage and validate the FASTA;
2. atomically acquire exact missing work when claims are supported, otherwise
   use legacy lookup;
3. send only acquired identities to the adapter in bounded batches while a
   renewal helper maintains their leases;
4. finalize locally computed terminal evidence with matching generations;
5. wait with bounded polling for busy keys, treating completed peer evidence
   as cache; and
6. materialize the unchanged DuckDB result.

`computed_sequences` counts only evidence calculated by the current
invocation. Evidence finalized by another invocation contributes to cached
sequences. Waiting is bounded by server expiry and renewal metadata; it does
not introduce a CLI knob.

## Compatibility Decisions

| Pair | Behavior |
| --- | --- |
| old client / new service | unchanged legacy endpoints and idempotent commits |
| new client / old service | capability detection falls back to released lookup/commit behavior |
| new claim client / new service | duplicate suppression for healthy owners; expiry recovery after death |
| stale owner / newer generation | renew, release, and finalize are rejected |

Legacy correctness remains the immutable evidence conflict check. Claims are
an optimization and coordination boundary, not an alternate evidence truth.

## Acceptance Gates

- Transport rejects malformed keys, semantic JSON, owner/generation values,
  response mismatches, and batches over 1,000.
- Busy responses expose no owner credential or generation and cannot populate
  renew, release, or finalize request models.
- A released-shape strict `HealthResponse` accepts the new service health body
  unchanged, and a missing capability endpoint selects legacy fallback.
- SQLite concurrency produces one healthy owner, supports renew/release and
  expiry takeover, rejects stale generations, and converges to one terminal
  record without residual claims.
- SQLite and PostgreSQL exact-expiry tests reject renew/release/finalize and
  require same-owner reacquire to advance generation after expiry.
- Real PostgreSQL through `SEQEVI_TEST_POSTGRES_URL` proves the same properties
  against the production transaction model and migration from `0002`.
- Two concurrent partially overlapping fixture annotations send each overlap
  to an adapter once, make the loser wait and reuse, produce equivalent DuckDB
  evidence, and classify peer work as cache rather than local compute.
- Hit and no-hit finalization, adapter failure cleanup, legacy endpoints, old
  service fallback, and claim residue checks pass.
- Store calls are chunked at 1,000 or fewer and adapters at 10,000 or fewer.
- The complete repository gate `pdm run check` passes.

No expensive real C2 execution starts as part of this change. After synthetic
and PostgreSQL acceptance, delivery reports the exact controller-owned host
command and input gate for separately coordinated C2 work.
