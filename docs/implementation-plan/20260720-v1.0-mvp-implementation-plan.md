# SeqEvi v1 MVP Implementation Plan

> Status: active
> Date: 2026-07-20
> Target: first reliable standalone release

## Objective

Build the smallest SeqEvi implementation that proves exact sequence reuse,
adapter isolation, immutable evidence, and local/shared Store parity. The MVP is
complete when the validation strategy passes, not when every possible annotation
tool or deployment is supported.

## Progress

As of 2026-07-21:

- Phase 0 repository, package, documentation, quality configuration, lock file,
  Python 3.12/3.13 CI, and MIT license are implemented.
- Phase 1 sequence identity and local Store core are implemented, including
  Alembic migration, atomic POSIX artifacts, exact hit/no-hit lookup, batch
  commit, conflict detection, and A/B/C incremental-reuse coverage.
- Phase 2 is implemented, including the process-group-aware tool runner,
  deterministic cache-miss FASTA, adapter protocol, `annotate` orchestration,
  Parquet/TSV materialization, and Data Package v2 descriptor.
- Phase 3 code and fixture contract tests are implemented. Official
  InterProScan 5.77-108.0 direct-tool parity remains the Phase 3 exit gate.
- Phase 4 code and fixture contract tests are implemented for the canonical
  eggNOG-mapper 2.x annotations schema. Official runtime/database parity remains
  the Phase 4 exit gate.
- Phases 5 and 6 have not started.

## Delivery Principles

- Implement local behavior before shared deployment.
- Freeze contracts with fixtures before adding real expensive tools.
- Reuse mature libraries at protocol boundaries.
- Keep external tools and databases outside the Python distribution.
- Add an abstraction only where local/shared or adapter behavior truly differs.
- Do not add Proteomics, WDL, Kubernetes, or project-management integration.

## Planned Package Shape

The exact module names may change during implementation, but ownership should
remain close to this shape:

```text
src/seqevi/
├── __init__.py
├── __main__.py
├── cli.py
├── sequence.py
├── evidence.py
├── runner.py
├── package.py
├── adapters/
│   ├── base.py
│   ├── eggnog.py
│   └── interpro_pfam.py
├── store/
│   ├── contract.py
│   ├── local.py
│   └── client.py
└── service/
    ├── app.py
    ├── config.py
    └── persistence.py
```

The adapter and Store boundaries use Python protocols or small abstract
interfaces only where tests require interchangeable implementations. Internal
values use frozen, slotted dataclasses. Pydantic models are reserved for CLI
configuration, manifests, and HTTP request/response validation.

## Phase 0: Repository Foundation

Deliverables:

- PDM package using `src/` layout and Python 3.12+;
- architecture, contract, plan, and validation documents;
- Ruff, Pyright, pytest, Hypothesis, and coverage configuration;
- CI jobs for Python 3.12 and 3.13;
- public license decision before the first external release.

Exit criteria:

- package imports in a clean environment;
- documentation links and project metadata validate;
- quality commands run from one documented entry point.

## Phase 1: Sequence Identity and Local Store

Implement:

- streaming FASTA records with `SimpleFastaParser`;
- normative canonicalization and whole-invocation validation;
- GA4GH `SQ.` and MD5 identifiers;
- `sequence-map.tsv` model;
- SQLite schema and Alembic migration;
- POSIX content-addressed artifact writes;
- exact lookup, atomic commit, fetch, hit, and no-hit states;
- explicit local `--store` resolution.

Use an in-process fake adapter to prove A/B/C incremental reuse before invoking
any scientific tool.

Exit criteria:

- a subset FASTA performs zero fake computations;
- a mixed FASTA computes only novel canonical sequences;
- invalid input commits nothing;
- concurrent duplicate local commits are idempotent.

## Phase 2: Tool Runner and Package Contract

Implement:

- private process-group-aware `ToolRunner`;
- timeout and cancellation cleanup;
- structured runtime result and diagnostics;
- deterministic cache-miss FASTA creation;
- thin normalized Parquet writing with Polars;
- Data Package v2 descriptor with the versioned `seqevi` extension;
- `evidence.parquet`, `sequence-map.tsv`, and `no-hits.parquet` materialization.

Use a deterministic fixture executable to test success, no-hit, malformed
output, non-zero exit, timeout, and interruption without third-party databases.

Exit criteria:

- the output package is reproducible apart from declared timestamps;
- every requested sequence is accounted for;
- failure diagnostics are useful and no failed evidence is cached.

## Phase 3: InterProScan Pfam Adapter

Status: implementation complete; official runtime/data parity pending.

Implement `interpro-pfam` first because it provides direct sequence-based Pfam
evidence and has a clear native TSV contract.

Deliverables:

- runtime/version probe and immutable digest configuration;
- InterPro/Pfam resource identity validation;
- typed semantic parameter model;
- native TSV validation and sequence-MD5 reconciliation;
- adapter-specific Parquet schema and no-hit classification;
- direct InterProScan parity fixtures;
- documentation for local executable and separately supplied container use.

The adapter accepts the exact upstream InterProScan `data/` directory. It reads
the runtime's native `interproscan.properties`, points a temporary native copy
at that directory, and does not republish or transform the database.

The normalized Parquet excludes the native TSV run-date column because it is an
operational timestamp. The compressed native TSV remains the retained raw
artifact. All scientific Pfam match columns remain row-level.

## Phase 4: eggNOG-mapper Adapter

Status: implementation complete; official runtime/database parity pending.

Deliverables:

- protein-mode command contract;
- runtime and eggNOG resource identity;
- semantic classification of search/taxonomy/output options;
- native annotations parsing and no-hit accounting;
- preservation of `seed_ortholog` semantics;
- auxiliary `PFAMs` retained without merging into direct Pfam evidence;
- direct eggNOG-mapper parity fixtures.

The adapter accepts the upstream eggNOG database layout and does not expose
DIAMOND as a separate adapter.

The `eggnog/1` contract is deliberately limited to eggNOG-mapper 2.x and its
canonical 21-column annotations table. A v3/v7 runtime requires a separate
adapter contract version because its defaults, database generation, and output
schema differ. The v1 normalized result keeps native columns, including
`seed_ortholog` and auxiliary `PFAMs`, and only adds canonical `SequenceID`.

## Phase 5: Shared Store Service

Implement after the local Store contract is stable:

- FastAPI application with lookup, commit, and fetch operations;
- PostgreSQL persistence through SQLAlchemy Core;
- first-start Alembic migration under a database advisory lock;
- streamed artifact upload/download with digest and size validation;
- HTTPX client implementing the same logical Store contract;
- batch limits, request timeouts, and bounded memory behavior;
- OpenAPI contract tests;
- deployment notes for a PostgreSQL database and one writable POSIX artifact
  directory.

The service remains passive. `annotate` still launches the external adapter on
the client compute host.

## Phase 6: Release Readiness

Deliverables:

- wheel and source distribution;
- minimal public README quick start using a fixture adapter or documented real
  adapter environment;
- versioned database migrations;
- compatibility matrix for SeqEvi, adapters, tools, and resource releases;
- security and backup deployment notes;
- benchmark report for parsing, lookup, package materialization, and duplicate
  compute frequency;
- separate runtime container recipes only where upstream redistribution permits.

Annotation databases are linked from documentation and never included in the
package or container.

## Dependency Policy

Use these mature implementations instead of duplicating them:

| Need | Dependency |
| --- | --- |
| FASTA record parsing | Biopython `SimpleFastaParser` |
| Typed CLI | Typer |
| Columnar evidence | Polars and Parquet |
| Data Package descriptor | `dplib-py` |
| Relational persistence | SQLAlchemy 2 Core and Alembic |
| PostgreSQL driver | Psycopg 3 |
| Shared HTTP service | FastAPI and Uvicorn |
| Shared HTTP client | HTTPX |
| Boundary validation | Pydantic and pydantic-settings |
| Property testing | Hypothesis |

Use the Python standard library for hashing, base64url, JSON canonicalization,
gzip compression, filesystem atomic replacement, and process execution.

Do not add pandas, PyArrow as a direct API dependency, Pandera, Redis, Celery,
Kafka, workflow-engine SDKs, Docker/Kubernetes SDKs, fsspec/S3, DVC, SeqRepo, or
axiomkit in v1 unless a measured requirement changes the architecture.

## Annotate CLI Shape

Phase 2 freezes the shared command vocabulary. Adapter-specific scientific
options remain owned by each explicit adapter:

```bash
seqevi annotate \
  --adapter interpro-pfam \
  --fasta proteins.fasta \
  --store /data/seqevi-store \
  --output results/pfam \
  --executable /opt/interproscan/interproscan.sh \
  --database /data/interproscan-5.77-108.0/data
```

```bash
seqevi serve \
  --database-url postgresql+psycopg://seqevi@postgres/seqevi \
  --artifacts-dir /data/seqevi-artifacts
```

Adapter-specific scientific options should be grouped under explicit adapter
configuration rather than copied into a large universal command signature.

## Open Decisions Before First Public Release

- Supported operating systems beyond Linux.
- Exact runtime digest rules for non-container installations.
- Stable HTTP endpoint paths and service compatibility policy.
- Maximum upload, batch, and sequence-size limits.
- Whether invocation timestamps are excluded from reproducible package digests.

These decisions do not change the approved sequence or evidence identity model.

## Definition of Done

V1 is done only when:

- both official adapters satisfy their contract tests;
- local and shared modes materialize equivalent packages;
- exact cache invalidation and no-hit caching are demonstrated;
- concurrent commits cannot overwrite evidence;
- every package is auditable to sequence, adapter, runtime, resource, and
  semantic parameters;
- the complete validation strategy passes in a clean release environment.
