# PostgreSQL Maintenance Acquisition Deadline Plan

Version: v1.0

Date: 2026-08-14

Status: implemented and validated

Issue: [#34](https://github.com/FuqingZh/seqevi/issues/34)

Applies to: [ClaimSession delivery rebaseline addendum v1.1](20260813-v1.1-claim-session-delivery-rebaseline-addendum.md)

## Scope

Close the PostgreSQL-only acquisition gap around ClaimSession Store maintenance.
Retain two independent fixed 60-second monotonic budgets: the mutation/fence
deadline and the separately started post-commit reconciliation deadline. Charge
both SQLAlchemy pool checkout and any new psycopg physical connection to the
positive remainder of the applicable original deadline.

This issue does not change SQLite, the public Store or CLI configuration
surface, HTTP transport, ClaimSession protocol edges assigned to issue #35, or
external-tool cleanup and pressure acceptance assigned to issue #37.

## Implementation

1. Add one private PostgreSQL acquisition boundary in
   `src/seqevi/store/migration.py`. The normal CLI creates and owns a fresh
   `Engine` immediately before maintenance. Fail fast before temporary listener
   installation if it already has an instance-local `checkout` or `do_connect`
   listener; arbitrary application hook execution is not part of this private
   CLI contract. Immediately before each `Engine.connect()`,
   compute the positive remainder, bound acquisition-boundary serialization by
   that deadline, clamp the engine QueuePool checkout timeout to the lesser of
   its existing value and a remainder recomputed immediately before checkout,
   and inject a psycopg `connect_timeout`
   no larger than the usable whole-second remainder for any new physical
   connection. After target resolution, recheck irreversible watchdog expiry,
   recompute that remainder and per-attempt timeout at the last boundary before
   `dialect.connect()`, and recheck expiry before physical creation. Respect
   libpq's effective two-second minimum and replace unset
   or zero values rather than preserving an unbounded physical connect. Resolve
   every hostname without a paired `hostaddr` through the existing isolated
   private resolver protocol under the same absolute deadline, with synchronous
   terminate/kill/exact-reap ownership that tolerates an already-exited child
   and applies to every exceptional communication exit without replacing its
   primary error. Expand only copied parameters into
   aligned libpq `host`/`hostaddr`/`port` targets, divide the post-resolution
   remainder across every actual address attempt, retain numeric IPv6 scope
   identifiers, reject unequal explicit nonempty `host` and `hostaddr` list
   lengths while broadcasting only an omitted or empty counterpart, and never
   retain resolved targets or the phase-local timeout in the Engine. Freeze
   effective PGHOST, PGHOSTADDR, PGPORT, PGCONNECT_TIMEOUT, and
   PGTARGETSESSIONATTRS values, treating null or wholly
   empty keyword values as omitted so environment fallback remains visible;
   preserve a positive effective connection timeout as a stricter cap after
   Psycopg-compatible fractional-to-whole-second conversion while replacing an
   unset or nonpositive value; double the attempt count for
   prefer-standby including hostless targets; use the active client libpq's
   compiled
   default only to resolve empty aligned port entries while preserving those
   empty outbound entries; and fail closed for service-derived targets whose
   external service-file attempt set is not auditable.
   Restore the pool timeout and private connect state immediately after checkout
   succeeds or fails; if the post-checkout deadline check fails, invalidate and
   close the acquired connection before propagating, attempting both cleanup
   steps and preserving the deadline failure if either cleanup step fails. Fail before physical
   acquisition when the remaining libpq-compatible interval cannot represent a
   bounded timeout of at least two seconds.
   Inspect connection invalidation before cleanup watchdog raw-handle discovery;
   never use a reconnecting SQLAlchemy accessor or reconnect an invalidated
   physical session after the temporary bounded listener has been removed.
   Keep a raw-connection cancellation watchdog active across SQLAlchemy
   checkout and first-connect dialect initialization. Expiry is irreversible:
   after expiry, continue low-frequency bounded psycopg `cancel_safe` calls for
   the published raw connection until acquisition unwinds. Publish reused raw
   connections before pre-ping and at the maintenance-owned checkout boundary
   without changing session or transaction state, preserve reconnect handling, and
   structurally restore both temporary internal boundaries on every path. Treat `/` filesystem
   Unix sockets as socket targets rather than DNS names, and reject Linux `@`
   abstract Unix socket targets before driver connect because psycopg would
   synchronously resolve them before raw-handle publication.
   Require psycopg's native bounded-cancel capability (client libpq 17+) before
   acquisition rather than relying on its potentially blocking compatibility
   fallback. Skip an individually unresolvable multihost target while another
   usable target remains, and fail only when all targets are unusable.
   Reject nonempty positional or keyword `conninfo` before physical connect,
   and let the maintenance-owned `do_connect` boundary perform physical
   creation after the fresh-Engine precondition excludes competing instance
   listeners.
   close a connection returned after expiry on its acquiring thread before
   initialization, and synchronously join the watchdog callback before yielding
   or propagating failure, and fail if that bounded join cannot prove the
   callback stopped. Invalidate and discard any assigned SQLAlchemy connection
   if initialization crosses the phase deadline or watchdog joining fails on
   either the success or error path, retaining primary-error cleanup notes.
   Deactivate the listener before removal so even a failed removal leaves an
   inert residual callback and later connections remain usable.
2. Use that boundary for the initial PostgreSQL mutation/fence connection and
   for every fresh PostgreSQL maintenance state readback, including readback
   after the mutation connection was invalidated. Do not create or reset either
   absolute deadline during acquisition.
3. Publish a v1.6 successor to the current storage-deployment architecture that
   preserves v1.5 and makes the two-budget acquisition contract explicit.
4. Add deterministic focused regressions for stalled QueuePool checkout and
   stalled physical connect in both mutation and reconciliation phases, plus a
   real PostgreSQL 17 invalidation/fresh-readback path. Preserve existing SQLite
   maintenance coverage unchanged.

## Risks and controls

- SQLAlchemy exposes no per-checkout timeout argument. The private boundary
  therefore temporarily narrows the existing QueuePool timeout under a module
  lock; the maintenance runbook already requires writers to be quiesced, and
  state is restored in `finally`.
- psycopg/libpq expresses `connect_timeout` in whole seconds and interprets one
  second as an effective two-second minimum. The boundary floors the positive
  remainder and refuses physical acquisition below two whole seconds
  rather than rounding beyond the deadline. Existing monotonic transaction and
  cleanup watchdogs continue to govern work after acquisition.
- libpq applies `connect_timeout` to each resolved or explicit address attempt,
  and its synchronous DNS is outside that timeout. Resolve configured hostnames
  first inside the phase deadline, then divide the floor of the remaining phase
  budget by the actual expanded address count; reject a new physical connection
  if the result cannot meet libpq's minimum.
- The synchronous wall-clock contract covers supported ordinary connection
  configuration, pool wait, isolated DNS, libpq network attempts, and
  SQLAlchemy initialization. OS-uninterruptible client-side file access such as
  FIFO or unavailable network-filesystem reads is unsupported; subprocess DBAPI
  proxying is deliberately outside this maintenance boundary.
- A checked-out pooled connection does not establish a new socket; it is still
  charged to pool checkout. A stale or invalidated connection that reconnects
  receives the phase-local physical-connect clamp through the same boundary.
