# Validation Strategy Addendum

Version: v1.2
Date: 2026-08-24
Status: approved validation strategy

This addendum extends the retained adapter, Store, result, CLI, packaging and
ClaimSession gates in [v1.1](../../testing/20260810-v1.1-validation-strategy.md). It adds the
following required checks for annotation progress observability.

## Progress Compatibility Gates

- Private event construction rejects partial, unitless, negative and
  over-complete ratios. Unknown work remains count-free.
- Cold compute and all-cache annotation preserve result behavior while
  producing the expected staging, lookup, tool, commit, fetch and package
  boundaries. Tool and commit events are absent on an all-cache invocation.
- Sink failure is logged and contained without changing the annotation result.
- The interactive renderer refreshes elapsed time from an injectable monotonic
  clock, never invents a percentage, stops its timer and clears its transient
  stderr line.
- `--progress` is opt-in and visible in `annotate --help`. Default, non-TTY and
  every `--json` path remain progress-free; successful and typed-error JSON
  retain the existing one-document stream contract.
- The application boundary keeps finalization active across Store teardown and
  result scanning. Managed OCI retains its inner command and receives only an
  outer annotation/finalization envelope.
- Cancellation, timeout, claim coordination, packaging and cleanup suites
  remain unchanged and green, followed by the complete `pdm run check` gate.

No real eggNOG, dbCAN or InterProScan rerun is required because the private
sink and stderr renderer do not change adapter commands, upstream outputs,
evidence identity, Store behavior or result content.
