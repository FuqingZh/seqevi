# Sequence Evidence Contract

Version: v1.5

Date: 2026-08-13

Status: historical; archived; see `docs/README.md` for current authority

Supersedes: [v1.4](20260813-v1.4-sequence-evidence-contract.md)

SeqEvi retains the v1.4 immutable evidence, invocation-scoped ClaimSession,
bounded authority-readback, generation-fence, locking, and compatibility
contracts. Each ClaimSession network operation has one absolute monotonic total
deadline covering connection acquisition, request upload, response headers,
and the complete response body. Expiry actively cancels and joins that request
before the synchronous caller resumes; it leaves no request worker or socket
operating in the background and does not cancel another session or request.

Capability discovery, open, renew, acquire, finalize, authority checks, close,
ClaimSession artifact upload, and finalize reconciliation use this boundary.
Acquire expiry cancels only that acquire and does not itself mark the session
lost. Renew `412` or renew-budget exhaustion promptly publishes session loss.
Finalize mutation and upload stop at a private earlier cutoff that reserves
positive reconciliation runway inside the original finalization budget.
Ambiguous outcomes then perform terminal-evidence lookup and, when needed,
exact authority checking without receiving a new budget.

The public Store API remains synchronous. Relative to v0.2.0, removal of
`HttpEvidenceStore(..., client=...)` is the sole intentional released Python
source incompatibility. Every other released constructor parameter,
synchronous method, and health, lookup, fetch, artifact, download, and legacy
commit wire behavior remains compatible. The unreleased per-key claim types,
helpers, and methods remain absent without aliases. Private transport injection
used by tests is not an application API.
