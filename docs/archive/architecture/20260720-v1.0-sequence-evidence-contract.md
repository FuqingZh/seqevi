# Sequence and Evidence Contract

> Status: historical; archived; see `docs/README.md` for current authority
> Contract version: 1.0
> Date: 2026-07-20

## Purpose

This document defines what SeqEvi considers the same protein sequence and the
conditions under which existing annotation evidence may be reused. These rules
are normative for local and shared Stores.

## FASTA Record Parsing

SeqEvi uses Biopython `SimpleFastaParser` as the streaming FASTA record parser.
For each record:

- `InputID` is the first whitespace-delimited token after `>`;
- `InputHeader` is the complete header text after `>`;
- `InputID` must be non-empty and unique within the invocation;
- record order is preserved in `sequence-map.tsv`.

The full header is invocation metadata. It is written to the output package but
is never persisted in the shared sequence Store. This prevents project,
customer, sample, or accession labels from becoming global sequence identity.

Different input IDs may resolve to the same canonical sequence. They remain
separate rows in `sequence-map.tsv` and map many-to-one to the same `SequenceID`.

## Canonical Protein Sequence

Canonicalization is deterministic and applies in this exact order:

1. Remove ASCII whitespace from the parsed sequence.
2. Convert ASCII letters to uppercase.
3. Remove at most one terminal stop marker (`*`).
4. Reject an empty result.
5. Reject any remaining `*`, gap character, digit, punctuation, or non-ASCII
   character.
6. Accept the remaining `A-Z` letters at the identity layer.

Ambiguous or uncommon alphabetic residue codes such as `B`, `J`, `O`, `U`, `X`,
and `Z` therefore have stable sequence identity. An adapter may reject a subset
that its external tool cannot process, but it may not rewrite the sequence to a
different identity.

Examples:

| Input sequence | Canonical result |
| --- | --- |
| `MKWVTFISLL` | `MKWVTFISLL` |
| `mkwv tfisll` | `MKWVTFISLL` |
| `MKWVTFISLL*` | `MKWVTFISLL` |
| `MKWV*TFISLL` | rejected |
| `MKWV-TFISLL` | rejected |
| `1234` | rejected |

If any FASTA record is invalid, the entire invocation fails before annotation or
Store commit. SeqEvi does not emit a partially successful evidence package.
`rejected.tsv` may be written as a failure diagnostic.

## Sequence Identifiers

The primary identifier is a GA4GH refget sequence identifier:

```text
SequenceID = "SQ." + sha512t24u(canonical_sequence_bytes)
```

`sha512t24u` is the first 24 bytes of SHA-512 encoded as unpadded URL-safe
base64. The bytes are the ASCII encoding of the canonical protein sequence.

SeqEvi also records a lowercase hexadecimal MD5 digest for compatibility with
tools and resources that use sequence MD5. MD5 is an alias and lookup aid, not
the primary integrity key.

On every existing identifier lookup, the Store verifies sequence length and
canonical sequence content. An identifier collision or mismatched payload is an
integrity error, never a cache hit.

## Minimal Persisted Sequence Record

The v1 Store persists only content identity:

| Field | Meaning |
| --- | --- |
| `sequence_id` | Primary `SQ.` identifier |
| `md5` | Compatibility digest |
| `length` | Canonical residue count |
| `sequence` | Canonical protein sequence |

The Store does not persist FASTA headers, project IDs, customer IDs, sample IDs,
source paths, inferred species, or user accessions in this table.

## Evidence Key

Evidence is reusable only when every component of this tuple matches exactly:

```text
EvidenceKey = (
    SequenceID,
    AdapterContractVersion,
    ToolRuntimeDigest,
    ResourceID,
    SemanticParameters,
)
```

Definitions:

- `SequenceID`: canonical content identity defined above.
- `AdapterContractVersion`: version of parsing, evidence semantics, and
  normalized adapter schema.
- `ToolRuntimeDigest`: immutable identity of the executable environment, such as
  an OCI image digest or an equivalent installed-runtime fingerprint.
- `ResourceID`: immutable identity of the exact third-party annotation database.
- `SemanticParameters`: canonical JSON containing all parameters that can change
  scientific results, including explicit defaults.

Canonical semantic parameters use JSON-compatible scalar/list/object values,
sorted object keys, stable numeric representation, and no machine-local paths.
The canonical JSON is hashed for indexing, while the complete value remains in
the run manifest for audit.

There is no nearest-version or latest-version lookup. A request for a new tool,
resource, parameter, or adapter contract never returns older evidence.

## Species and Taxonomy

SeqEvi v1 does not infer species. A taxonomy identifier is optional invocation
configuration only when an adapter genuinely consumes it. It participates in
`SemanticParameters` only in that case.

Taxonomy labels supplied only for reporting do not alter sequence identity or
the evidence key. An eggNOG `seed_ortholog` or other hit organism must never be
treated as the source protein's own identity or inferred species.

## Evidence States

For each exact evidence key, the Store can contain one immutable terminal state:

- `hit`: validated normalized evidence exists;
- `no_hit`: the external tool completed successfully and produced no evidence
  for the sequence.

`no_hit` is cached. Re-running the same exact contract must not repeat expensive
annotation merely because no rows were found.

Failures, timeouts, malformed outputs, and adapter rejections are not terminal
evidence and are not reusable cache entries.

## Immutability and Concurrency

Evidence is insert-only in v1. Older tool/database/parameter versions remain
available and are never overwritten or automatically deleted.

SeqEvi does not implement leases, heartbeats, or a distributed scheduler. Two
clients may compute the same cache miss concurrently. The Store uses a unique
evidence key and atomic commit:

- identical valid results converge on one committed record;
- a later identical commit is idempotent;
- different payloads for the same exact key raise an integrity error.

## Invocation Sequence Map

Every successful output package includes `sequence-map.tsv` with at least:

| Column | Meaning |
| --- | --- |
| `InputOrder` | One-based order in the input FASTA |
| `InputID` | First FASTA header token |
| `InputHeader` | Complete input header |
| `SequenceID` | Canonical `SQ.` identifier |
| `MD5` | Compatibility digest |
| `Length` | Canonical sequence length |
| `EvidenceStatus` | `hit` or `no_hit` for this adapter contract |
| `EvidenceSource` | `cache` or `computed` for this invocation |

This file is the explicit bridge between ephemeral FASTA labels and reusable
content evidence.

## SeqRepo Relationship

SeqRepo is relevant prior art for non-redundant sequence storage, digest-based
identifiers, aliases, snapshots, and random sequence access. SeqEvi does not use
it as a v1 runtime dependency because SeqEvi accepts full FASTA sequence content
and needs annotation evidence identity rather than a general sequence-reference
repository.

If SeqEvi later accepts accession-only input, a narrow `SequenceProvider`
interface may resolve accessions through refget or a SeqRepo service before this
canonical sequence contract is applied.
