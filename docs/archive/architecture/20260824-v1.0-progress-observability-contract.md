# Annotation Progress Observability Contract

> Status: historical; archived; see `docs/README.md` for current authority
> Contract version: 1.0
> Date: 2026-08-24

## Scope

`seqevi annotate --progress` gives an interactive user SeqEvi-owned phase,
liveness and exact-count progress. The flag is boolean and opt-in. Progress is
disabled by default, when stderr is not a TTY, and for every `--json`
invocation.

This contract applies equally to local eggNOG-mapper, dbCAN and
InterProScan/Pfam orchestration. It does not normalize or interpret the three
tools' native console output.

## Output Boundary

Progress is a transient, single-line stderr presentation. The existing final
human summary remains on stdout. After successful CLI parsing, `--json`
continues to produce exactly one JSON success document on stdout or one typed
application-error document on stderr; progress never appears in either stream.

The renderer reports a percentage only when an event carries an exact
`completed`, `total` and typed unit for the same SeqEvi-owned work. An unknown
tool-batch total, process activity and elapsed time are liveness rather than a
percentage or estimated completion time.

## Internal Event Boundary

The private immutable event contract covers these phases:

```text
annotation
staging
store_lookup
claim_wait
tool
store_commit
store_fetch
package
finalization
completed
```

The private sink is threaded through the shared application boundary and
shallow annotation orchestration. It is not exported from `seqevi`, does not
change the public `seqevi.annotate()` signature, and is not a public callback
or serialization format.

The application boundary alone emits `finalization` before local Store
teardown and result re-open, or before managed-result validation. It emits
terminal completion only after those operations succeed. Managed OCI keeps its
existing inner one-document `--json` command unchanged and receives only an
outer liveness envelope.

## Failure And Compatibility

Progress delivery and renderer failures are logged and contained. They cannot
change evidence computation, Store mutation, result publication, cancellation,
timeout or process cleanup. The renderer timer stops and its transient line is
cleared on successful, typed-error and untyped-exception paths before existing
final output is written.

This feature changes no adapter command, upstream stdout/stderr file, Store or
EvidenceKey coordinate, ToolRuntimeDigest, ResourceID, batch size, DuckDB
schema, scientific result or dependency.
