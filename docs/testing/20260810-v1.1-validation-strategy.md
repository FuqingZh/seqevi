# Validation Strategy

Version: v1.1
Date: 2026-08-10
Status: approved validation strategy

This strategy supersedes
[v1.0](20260720-v1.0-validation-strategy.md) and retains all released adapter,
Store, result, CLI, and packaging gates. Evidence claim coordination adds the
following required checks before delivery.

## Claim Contract Gates

- Strict domain and transport invariants, owner-token redaction, busy responses
  without authority, exact response membership, HTTP 409 conflict versus 412
  lease-loss mapping, batch limits, and duplicate mutation rejection.
- Frozen released-shape `/health` parsing, new-client/old-service HTTP 404
  fallback with working legacy lookup/commit, and no fallback for auth or 5xx.
- SQLite concurrency, expiry boundaries, release-generation ABA prevention,
  stale mutation rejection, legacy terminal cleanup, and zero terminal claim
  rows.
- SQLite and real PostgreSQL migration from seeded `0002` sequence, artifact,
  hit, and no-hit rows with every legacy field unchanged after `0003`.
- Real PostgreSQL one-winner acquisition, renew/release, expiry before and after
  takeover, stale finalize rejection, canonical multi-key locking,
  finalize/acquire takeover, and legacy-commit/finalize races.
- Partial-overlap annotation with an observed BUSY state, winner compute and
  loser cache classification, equivalent DuckDB results, and zero residue.
- Exact 10,001-miss adapter boundary of two tool calls, plus a 1,500-key forced
  renewal/finalize race proving `[1000, 500]` Store chunks and renewal of only
  the remaining claims.
- Failure cleanup, hit/no-hit convergence, legacy endpoint behavior, focused
  suites, then the complete `pdm run check` gate with
  `SEQEVI_TEST_POSTGRES_URL` configured.

Expensive real C2 annotation is explicitly outside this feature gate. It may
start only after synthetic and PostgreSQL checks pass and under separately
coordinated controller authority.
