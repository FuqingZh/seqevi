# Validation Strategy Addendum

Version: v1.3
Date: 2026-08-24
Status: approved validation strategy

This addendum supersedes the progress-specific gates in
[v1.2](../archive/testing/20260824-v1.2-validation-strategy.md) and extends the retained adapter,
Store, result, CLI, packaging and ClaimSession gates in
[v1.1](20260810-v1.1-validation-strategy.md).

## Semantic Progress Gates

- `WorkProgress` rejects negative and over-complete work; `BatchProgress`
  rejects non-positive batch values.
- The denominator is unique sequence content after FASTA staging, not FASTA
  record count.
- Readiness is cumulative and monotonic across initial cache hits, local Store
  finalization and peer-finalized evidence. A SequenceID is counted once.
- Cold, all-cache, mixed-cache and duplicate-content fixtures preserve Store
  evidence and result behavior. Tool and commit boundaries remain absent on an
  all-cache invocation.
- Active tool execution is indeterminate; batch metadata does not become a
  subprocess percentage.
- Sink failure remains logged and contained without changing the annotation
  result.

## Presentation And CLI Gates

- Deterministic full-width rendering contains the active phase, exact bar,
  `completed/total`, percentage and elapsed time derived from one work value.
- Compact rendering drops the bar while retaining active work, exact counts,
  percentage and elapsed time without wrapping.
- A full readiness value during finalization hides the completed bar and keeps
  the active phase visible.
- The Rich live region refreshes elapsed time from an injectable monotonic
  clock and is stopped and cleared idempotently.
- A capable TTY enables progress by default. `--progress` remains accepted,
  `--no-progress` disables it, and non-TTY, `TERM=dumb` and every `--json` path
  remain progress-free.
- `annotate --help` exposes the paired option spellings.
- The durable human summary retains unique, cached, computed and output values
  and adds total invocation elapsed time.
- Successful and typed-error JSON paths retain the existing one-document
  stream contract.
- Managed OCI retains its inner command and exposes outer liveness without a
  ratio.

## Regression And Release Gate

Focused progress, annotation, API, CLI, OCI, cancellation and cleanup tests run
first. The exact final tree must then pass the repository-owned `pdm run check`
gate before implementation is claimed complete.

No real eggNOG, dbCAN or InterProScan rerun is required because this private
event and terminal presentation successor does not change adapter commands,
upstream outputs, evidence identity, Store behavior or result content. A
focused failure indicating execution-boundary drift reopens that decision.
