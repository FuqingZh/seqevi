# Storage Deployment Architecture

Version: v1.4

Date: 2026-08-13

Status: approved target architecture; activation pending

Supersedes: [v1.3](20260812-v1.3-storage-deployment-architecture.md)

Revision `0004_claim_sessions` and all migration, fencing, preservation, and
PostgreSQL maintenance contracts remain as specified by v1.3. Sweepers delete
at most 1,000 rows from each coordination class per transaction.

LocalStore gives its private SQLite sweeper a short writer-lock budget. Stop,
join, and the final drain have fixed bounds; contention may leave ephemeral
coordination rows for deterministic recovery by the bounded drain on the next
Store open. Interrupted teardown never weakens generation fences or deletes
terminal sequence, artifact, or evidence data.

Before SQLite maintenance takes the file fence or executes destructive DDL, it
resolves a relative database URL to the existing canonical absolute
`store_root/store.sqlite3` file. The supplied Store root, database target, and
operator acknowledgement must identify that one file. Missing or ambiguous
targets, acknowledgement mismatch, symlink targets, and paths outside or not
equal to the Store database fail closed.
