# SeqEvi v1.3 InterPro Runtime Identity Contract

> Status: approved target architecture
> Contract version: 1.3
> Date: 2026-08-21
> Supersedes: InterPro runtime-identity portions of [v1.2](20260814-v1.2-adapter-contract.md)

## Scope

The adapter, result, cancellation, resource and Store boundaries in v1.2 stay
normative. This version changes only the active InterProScan Pfam adapter and
runtime identity for the SeqEvi 0.3.2 candidate. It adds no API, Store schema,
dependency, plugin, compatibility shim or generic tree-hash facility.

## InterProScan Pfam v2

The active adapter contract is `interpro-pfam/2`. The resolved `java`
executable must have the `JAVA_HOME/bin/java` layout. In addition to the
InterProScan launcher, runtime JAR, normalized properties and selected HMMER
files, `ToolRuntimeDigest` hashes the selected JDK's result-producing runtime
image: its `release` file and every regular file below `bin`, `conf` and `lib`,
including the module image, native libraries and configuration. Java 11 and
newer must provide `lib/modules` as a regular file, and none of the three
runtime directories may be empty. Stable logical names rooted at `jdk/` make
identical runtime images at different filesystem paths equal.

The supported InterProScan launcher selects `java` from `PATH` and does not
consult `JAVA_HOME`. Adapter construction freezes the effective profile or
inherited `PATH` and uses that same value for version probing, runtime identity
and execution. Every entry must be a non-empty absolute path so adapter
discovery and launcher execution cannot resolve different binaries from their
different working directories.

Adapter construction fails closed when a required directory or release file
is missing, an entry is unreadable or non-regular, a symbolic link makes the
selected runtime ambiguous, or the enumerated runtime changes while it is
being hashed. Internal JDK symbolic links are deliberately unsupported: a JDK
distribution that uses them must be materialized as a stable regular-file tree
or replaced before SeqEvi can use it. Paths and filesystem metadata detect
drift during construction but do not enter the resulting digest.

Historical `interpro-pfam/1` Store rows remain readable through the unchanged
Evidence and Store formats. Adapter contract version is already an
`EvidenceKey` coordinate, so v2 lookups and writes naturally use keys distinct
from v1. Neither version may reinterpret the other's cached evidence.
