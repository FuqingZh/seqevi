## Decision

This document records a read-only assessment of product, architecture, and
code quality for the SeqEvi 0.3.5 source tree. It does not supersede any
document marked `Status: approved target architecture`. It does not change
evidence identity, adapter schemas, Store wire protocol, result format, or
cache behavior.

If this review and an approved contract disagree about runtime behavior, the
approved contract remains authoritative until a later versioned successor
updates it. If this review and implementation disagree, treat the disagreement
as a defect against the approved contract or against this recorded finding,
not as permission to reinterpret identity.

## Verdict

The scientific core is an independent protein sequence evidence cache with
exact immutable reuse, one adapter per invocation, adapter-native DuckDB
delivery, and caller-owned annotation databases. Official-runtime parity,
local and shared Store paths, and managed dbCAN setup exist in this tree.

The public product surface and documentation authority no longer describe one
v1 architecture. README, the July 20 overview, and the CLI disagree about
commands, adapters, Docker, and managed setup. ClaimSession and operator
maintenance now dominate complexity relative to the shallow `annotate` path
required by repository guidance.

Approximate inspected size of this tree: 17,186 lines under `src/seqevi`,
16,194 lines under `tests`, and 92 Markdown files under `docs/` totaling about
17,713 lines.

## Scope And Method

The review read the documentation index, current contracts listed there, the
July 20 overview, `AGENTS.md`, `README.md`, `pyproject.toml`, the public CLI
and Python API, and the annotate / adapter / Store / service / distribution
modules. It compared those surfaces with the 0.3.5 source and with the
capability table in `docs/README.md`.

It is not an acceptance gate, not a scientific re-run of eggNOG, InterPro, or
dbCAN, and not a license review. Incomplete Slice D, D5, and InterPro
target-Store records remain as previously recorded.

## Product And Documentation

### Strengths

- The reusable unit remains canonical protein sequence content under an exact
  evidence key. There is no `latest` fallback.
- The public Python API is `annotate` and `scan_annotations` returning native
  DuckDB relations (`src/seqevi/__init__.py`).
- `docs/README.md` does not rewrite Slice D, D5, or InterPro target-Store as
  passes.
- `AGENTS.md` still states the product boundary that the scientific path

## Architecture

### Strengths

- Evidence identity is the five-tuple SequenceID, adapter contract version,
  ToolRuntimeDigest, ResourceID, and canonical semantic parameters.
- One adapter per invocation; adapter schemas remain separate; DuckDB is an
  invocation snapshot, not a Store coordinate.
- Distribution stays off the scientific path. Adapters do not import Docker.
  OCI dispatch lives in `src/seqevi/distribution/` and is selected at the
  application boundary (`src/seqevi/api.py`).
- The shared Store service remains passive: lookup, commit, fetch, and
  ClaimSession coordination, with no tool scheduling
  (`src/seqevi/service/app.py`).
- Subprocess construction uses argument arrays. `shell=True` is absent from
  source.

## Code Quality

### Strengths

- Frozen identity objects validate canonical sequence, GA4GH `SQ.` identifiers,
  and MD5 aliases (`src/seqevi/sequence.py`).
- POSIX CAS paths accept only a lowercase SHA-256 digest, hash on write, and
  publish with `os.link` plus directory `fsync`
  (`src/seqevi/store/artifact.py`).
- FASTA staging validates the whole input and writes bounded NDJSON before
  Store access (`src/seqevi/sequence.py`).
- CI runs `pdm run check` on Python 3.12 and 3.13 with PostgreSQL 17
  (`.github/workflows/ci.yml`).
- Managed image references are digest-pinned. Credential-bearing shared Store
  URLs are rejected on the OCI path (`src/seqevi/distribution/oci.py:251-257`).

### Findings

Severity here is `bug` for incorrect or lossy runtime behavior, `suggestion`
for a real reliability or security gap that is not a silent scientific
rewrite, `observation` for a product decision, `contract check` for behavior
confirmed as required, and `nit` for leftovers.

#### C-1 — Severity: bug

- File: `src/seqevi/distribution/oci.py:178-197`
- Description: `run_oci_annotation` never records the original annotation
  error. `failure` is set in `finally` only when `docker rm` fails. A raise in
  `finally` replaces a pending `AnnotationError`. A successful `return` after
  `_publish_without_overwrite` is abandoned if cleanup fails, leaving a
  published DuckDB file and a failed process.
- Suggestion: capture the primary exception; always attempt `rm --force`;
  attach cleanup failure with `add_note` or `__context__`. Do not raise cleanup
  over an annotation failure. If publication already succeeded, do not convert
  cleanup failure into a missing-output error.
- Tests: `tests/test_oci.py` does not cover `rm` failure after `create`.

#### C-2 — Severity: contract check; not a defect

- File: `src/seqevi/store/client.py:924-965`
- Description: `finalize_many` computes one 30-second-or-lease deadline and
  shares it across split batches and artifact uploads. This is the exact
  storage v1.6 contract: one public finalize call owns one absolute budget and
  reserves reconciliation runway inside that budget. Acquire is a different
  public operation and intentionally takes a fresh window per chunk.
- Evidence: `tests/test_shared_store.py::test_finalize_batch_split_and_artifacts_share_one_absolute_budget`
  fixes `maximum_batch_size` at one and asserts the common cutoff.
- Decision: preserve the shared deadline. Do not give each finalize chunk a
  fresh budget without an approved storage-contract successor.

#### C-3 — Severity: suggestion

- File: `src/seqevi/service/app.py`, `deploy/httpd/seqevi-store.conf:18-20`
- Description: the shared Store has no application authentication. Trust is
  CIDR at private-cluster ingress. Anyone who can reach the API can upload
  artifacts up to `maximum_artifact_bytes` and `POST /v1/evidence/commit`.
- Suggestion: keep network isolation explicit on `seqevi serve`, or add an
  optional service token before any public bind.

#### C-4 — Severity: contract check; not a defect

- File: `src/seqevi/store/local.py:495-499`,
  `src/seqevi/service/persistence.py:1073-1078`
- Description: `commit_many` deletes the matching live `session_claims` before
  insert. This is the accepted v0.2.0 compatibility rule, not an undocumented
  hole: a legacy client cannot join ClaimSession, may duplicate active work,
  and may win the exact-key race. The locked transaction retires the claim and
  immutable convergence prevents overwrite or scientific conflict.
- Decision: preserve legacy commit behavior. Add a direct SQLite/PostgreSQL
  regression test for both race winners and conflict if current coverage does
  not make this compatibility boundary obvious.

#### C-5 — Severity: observation

- File: `src/seqevi/annotate.py:366-376`
- Description: `--timeout-seconds` is documented and passed only as an
  external-tool timeout. The
  BUSY loop sleeps on peer `retry_after` with no invocation deadline. A peer
  whose heartbeat thread remains alive can renew the 120-second lease
  indefinitely. `_CLAIM_RUNWAY_SECONDS` in `src/seqevi/annotate.py` is unused.
- Decision: document that peer wait is lease-driven and independent of the
  external-tool timeout. A whole-invocation deadline would be a separate
  public product contract, not a bug fix. Remove the unused
  `_CLAIM_RUNWAY_SECONDS` constant.

#### C-6 — Severity: bug

- File: `src/seqevi/store/client.py:1126-1130`, `src/seqevi/annotate.py`
- Description: after an unknown finalize response, matching readback is
  recorded as `CommitOutcome.EXISTING`. `run_annotation` treats every
  `EXISTING` as a peer win and rewrites provenance to cache. A worker that
  actually committed, then timed out, is labeled `EvidenceSource.CACHE`.
  Scientific rows can still be correct; invocation provenance is not.
- Suggestion: distinguish self-reconciled success from peer finalization, or
  document that unknown-success finalize is observationally a cache hit.

#### C-7 — Severity: suggestion plus observation

- File: `src/seqevi/distribution/oci.py:425-428`
- Description: `_mount` interpolates the source path into Docker `--mount`
  CSV. A comma in a FASTA, resource, or Store path injects extra mount keys.
  Docker is invoked with an argv list (`shell=False`); this is parser
  injection, not shell injection. Reject mount-separator characters in source
  paths, or use a non-CSV bind form.
- Observation: shared-Store OCI uses `--network bridge`. That matches the
  approved managed-distribution contract, which enables networking only for an
  explicit shared HTTP(S) Store; restricting egress to only that Store would be
  a new hardening contract.

#### C-8 — Severity: suggestion plus contract check

- File: `src/seqevi/store/local.py:193-202`
- Suggestion: the local claim sweeper re-raises any non-busy
  `OperationalError`, which kills the daemon thread. Stale claims then sit
  until process `close()` drain. The PostgreSQL sweeper logs and continues
  (`src/seqevi/service/app.py:99-103`). Log and continue on local sweep errors,
  matching the service sweeper.
- Contract check: local `ClaimSession.close` can fail while a heartbeat still
  owns work. `annotate.py` then unlinks only the output inode it published.
  This is deliberate fail-closed behavior: authority loss or cleanup failure
  must not leave a successful result. Do not remove `unlink_owned_output`
  without a contract successor and replacement safety proof.

#### C-9 — Severity: bug

- File: `src/seqevi/result.py:84-85`, `src/seqevi/result.py:164`
- Description: `materialize_result_database` rejects an existing output path
  then later `os.replace`, which replaces a racing file. The ClaimSession path
  uses `os.link` and is race-safe (`src/seqevi/annotate.py:551`).
- Suggestion: publish non-session results with `os.link` or equivalent
  no-overwrite publish.

#### C-10 — Severity: nit

Unused leftovers: `_HANDOFF_SCHEDULING_SECONDS`,
`_CLAIM_MUTATION_CHUNK_SIZE`, `_MAX_CONCURRENT_CLAIM_REQUESTS`,
`_RESERVED_CLAIM_RENEWAL_SLOTS`, and `_MAX_CLAIM_BACKPRESSURE_RETRIES` in
`src/seqevi/store/client.py:85-89`; `_CLAIM_RUNWAY_SECONDS` in
`src/seqevi/annotate.py`; `_local_receipt_item` in
`src/seqevi/store/local.py`; `_observe_claim_request` in
`src/seqevi/service/app.py`. Annotator acquire and finalize are sequential;
the unused concurrency-named constants should not imply an active concurrent
request design.

`AnnotationSummary.output_dir` names a DuckDB file. Renaming it is cleanup, not
a correctness repair, and must preserve any supported source compatibility.
`src/seqevi/result.py`
still carries the Slice A prototype helper. Adapter registry retains an
unreachable unavailable-adapter path.

## Test Gaps

Focused tests that are absent relative to the defects above:

- Docker `rm` failure after successful publication and during annotation
  failure (`tests/test_oci.py`).
- Legacy `POST /v1/evidence/commit` racing a live ClaimSession, preserving both
  accepted winner orders and immutable conflict behavior.
- Annotate BUSY wait versus `--timeout-seconds`.
- HTTP unknown-outcome finalize flowing through `run_annotation` provenance.
- Mount source paths containing `,`.

Same scientific `payload_digest` with different Parquet bytes is accepted
contract, not a bug.

## Out Of Scope

This review does not authorize managed eggNOG or InterPro onboarding, public
progress protocols, ETA, multi-input scheduling, global cache-seeding
expansion, or a D5 same-key managed contention gate. Those remain later
feature work or existing incomplete records.
