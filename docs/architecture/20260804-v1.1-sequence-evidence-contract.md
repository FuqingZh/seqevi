# SeqEvi v1.1 Sequence And Evidence Result Contract

> Status: approved target architecture
> Contract version: 1.1
> Date: 2026-08-04
> Supersedes: result-consumption portions of `20260720-v1.0-sequence-evidence-contract.md`

## Scope

The v1.0 canonical sequence, `SQ.` identifier, MD5 alias, evidence key,
terminal states, and Store immutability rules remain unchanged. This document
specifies how those identities are exposed in one queryable invocation result.

## Sequence Map

`main.sequence_map` has one row for every input FASTA record, in input order:

```text
InputOrder, InputID, InputHeader, SequenceID, MD5, Length,
EvidenceStatus, EvidenceSource
```

`InputID` and `InputHeader` are invocation labels. `SequenceID` remains the
content identity and the only join key between the map and adapter evidence.
Different input IDs with identical canonical sequence content therefore map to
one Store evidence record while retaining separate result rows.

## Annotation View

`main.annotations` is a left join from `sequence_map` to the selected adapter's
native `main.evidence` table on `SequenceID`. It places the eight sequence-map
columns before adapter-native columns. This makes the ordinary user operation
direct:

```python
annotations.select("InputID", "SignatureAccession")
```

The view intentionally has the adapter's row grain. An InterPro/Pfam protein
with multiple domains appears once per domain; a no-hit input still appears
with null evidence fields. Downstream joins at one-row-per-protein grain must
aggregate first when the adapter is one-to-many.

## No-Hit View

`main.no_hits` is a view with one row per unique canonical `SequenceID` whose
selected evidence key reached terminal `no_hit`. It contains `SequenceID`,
`MD5`, and `Length`. Duplicate input records do not duplicate this canonical
no-hit relation.

Failures, malformed output, timeouts, and adapter rejection remain non-terminal
and are never published as evidence or as a successful result file.

## Discovery And Versioning

The `_seqevi.column_info` catalog describes all public relation columns and
their DuckDB types. Consumers do not need an internal `seqevi.columns` module,
and result files never require a caller to remember the adapter's internal
contract revision. `ResultFormatVersion`, `ResultSchemaID`, and
`AdapterContractVersion` are recorded independently in `_seqevi.metadata`.
