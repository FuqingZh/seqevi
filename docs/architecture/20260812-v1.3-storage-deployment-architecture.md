# Storage Deployment Architecture

Version: v1.3

Date: 2026-08-12

Status: proposed current-on-merge architecture; implementation in progress

Supersedes: [v1.2](20260810-v1.2-storage-deployment-architecture.md)

Revision `0004_claim_sessions` replaces ephemeral 0003 leases with session,
exact-key generation, open-receipt, and normalized acquire-receipt tables.
Foreign keys restrict deletion; renew and close touch one session row; sweepers
delete at most 1,000 rows from each coordination class per transaction.

Fenced pristine creation may bootstrap directly to 0004. Existing 0001/0002
Stores advance no further than 0003; existing 0003 and ambiguous unversioned
Stores fail closed for explicit maintenance. Only ephemeral claims are
invalidated; sequence, artifact, evidence, and result data are preserved.

PostgreSQL maintenance uses the legacy advisory lock, one 60-second monotonic
deadline, a complete `ACCESS EXCLUSIVE` fence, and session
`transaction_timeout` configured in autocommit across a protocol Sync boundary
before a distinct `BEGIN`. Cleanup resets and reads back the timeout; uncertainty
invalidates the physical connection. SQLite uses nonblocking file-lock polling,
`BEGIN EXCLUSIVE`, the same deadline, and a progress handler through DDL and
revision writes.
