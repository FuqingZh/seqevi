# Execution Profile Contract

> Status: approved target architecture
> Contract version: 1.0
> Date: 2026-07-24

## Purpose

SeqEvi execution profiles remove repeated machine-local adapter setup from the
high-frequency annotation path. A profile names the external launcher, its
native annotation resource, operational defaults and the environment needed to
start that runtime.

Profiles do not define scientific semantics. Adapter contract versions continue
to materialize and hash every result-affecting parameter. SeqEvi remains
independent of biofetch and does not download, install or update external tools
or resources.

## Selection Modes

`seqevi annotate` has three explicit, mutually exclusive identity modes:

1. `--profile NAME` loads
   `${XDG_CONFIG_HOME:-~/.config}/seqevi/profiles/NAME.toml`.
2. `--config PATH` loads one exact execution-profile TOML document.
3. Explicit mode requires `--adapter`, `--executable` and `--resource`.

`--profile` is the ergonomic path for repeated use. `--config` is the
automation and reproducibility path for a file at a caller-controlled location.
There is no mutable current profile, implicit default profile, repository
directory discovery or partial merging of identity fields.

Invocation inputs `--fasta` and `--output` always remain explicit. `--store`,
`--threads` and `--timeout-seconds` may override profile operational defaults
for one invocation. Explicit scientific identity fields cannot be combined
with a selected profile.

## Profile Document

Version 1 uses one complete TOML document per profile:

```toml
version = 1
adapter = "interpro-pfam"
executable = "/opt/interproscan/interproscan.sh"
resource = "/opt/interproscan/data"
store = "/data/seqevi-store"
threads = 8
# timeout_seconds = 86400
path_prepend = ["/opt/jdk-17/bin"]
```

Required keys are `version`, `adapter`, `executable` and `resource`. Optional
keys are `store`, `threads`, `timeout_seconds`, `path_prepend` and
`environment`.

Unknown keys, unknown adapters, unsupported document versions, invalid types,
unsafe profile names and invalid paths fail before Store lookup or external
execution. Relative filesystem paths are resolved against the profile file,
not the caller's working directory. Bare executable names use the profile
`PATH` when supplied and otherwise use the inherited process path.

`path_prepend` resolves directories relative to the profile and prepends them
to the effective process `PATH`. This is the preferred way to select supporting
executables such as InterProScan's Java runtime without copying the caller's
entire `PATH` into TOML.

The environment table is an optional explicit string-to-string subprocess
overlay. The resolved path and environment apply consistently to runtime
discovery, version probes and annotation execution. They are operational
configuration and do not weaken the adapter's immutable runtime digest or
resource identity checks.

## Public Vocabulary

The public CLI uses `resource` for the native upstream database tree consumed
by an adapter:

```text
--resource /data/eggnog-5.0.2
--resource /opt/interproscan/data
```

`--database` is not retained as a compatibility alias. Internal adapter code
may continue to use database-specific terminology where it describes an
upstream format precisely.

## Authoring And Inspection

SeqEvi provides a complete adapter-specific template through:

```bash
seqevi profile example --adapter interpro-pfam
seqevi profile example --adapter eggnog
```

`seqevi profile validate --config PATH` validates one document and its local
paths without launching the annotation runtime.

Named profile authoring and inspection use:

```bash
seqevi profile init NAME --adapter eggnog
seqevi profile list
seqevi profile show NAME
```

`init` writes one complete adapter-specific document and fails if the
destination exists. `list` is lexically sorted. `show` uses the same strict
loader as annotation and displays resolved effective paths and operational
defaults. It may display environment variable names but never their values;
credentials and query parameters in Store URLs are also redacted.

These commands do not edit or delete profiles and do not mutate a shared
multi-profile document. The TOML file remains the source of truth and must stay
easy to review, copy and version outside SeqEvi.

## Deliberate Boundaries

- No generic plugin or arbitrary command-template system.
- No embedded resource downloader, registry or biofetch awareness.
- No secrets store; credentials belong in an external secret mechanism or
  process environment.
- No project-scoped profile inheritance in v1.
- No automatic resource-version selection or best-effort fallback.
- No universal annotation schema or cross-adapter result merge.

## Managed Evolution

This v1 contract remains the current host-runtime profile behavior. `profile
init` only writes a host-runtime template; it does not install a launcher,
supporting executables, or annotation resources. The current `seqevi setup`
command implements the separate managed-profile v2.2 contract for dbCAN only;
it does not supersede or change v1 host-runtime profiles.
