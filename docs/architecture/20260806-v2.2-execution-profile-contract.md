# Execution Profile Contract

Version: v2.2
Date: 2026-08-06
Status: approved target architecture; dbCAN managed acceptance passed
Supersedes: [v2.1](../archive/architecture/20260805-v2.1-execution-profile-contract.md)

## Scope

This version inherits v2.1 and revises only release-candidate validation and
scientific parity. Public setup and profile behavior remain strict: the
`dbcan-cazyme` managed profile contains the bundled digest-pinned GHCR image.
No public option, environment variable, mutable tag, site profile, or
persistent override can replace it.

## Validation Candidate

Release validation may replace the launch image with an immutable local image
ID only inside the current process's validation harness. The replacement is
not serialized, is not a profile field, and does not modify the public kit.
The candidate must be release-equivalent under the v1.2 distribution
architecture and must not masquerade as the public digest.

## Acceptance

Direct and managed executions of the same candidate require equal
`ToolRuntimeDigest`, adapter contract, semantic parameters, `ResourceID`,
scientific values, hit/no-hit classification, and public DuckDB schema. A
separate host installation may have a different exact `ToolRuntimeDigest`, but
all other scientific and schema identities remain equal.

Managed acceptance additionally requires cold execution and a later-process
Store replay with 50 cache hits and 0 computed records, read-only caller input
and resource mounts, caller UID/GID, `--network none` for a local Store, and no
residual annotation container.
