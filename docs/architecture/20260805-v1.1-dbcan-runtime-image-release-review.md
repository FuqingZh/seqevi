# dbCAN Runtime Image Release Review

> Status: approved release boundary; runtime artifacts pending
> Date: 2026-08-05
> Supersedes: [v1.0 redistribution review](20260805-v1.0-dbcan-redistribution-license-review.md)

## Decision

SeqEvi may publish a public, first-party dbCAN runtime image after the runtime
artifact checklist below passes. The image contains SeqEvi, dbCAN, DIAMOND,
Python and their resolved runtime dependencies. It does not contain, download,
copy or redistribute the dbCAN annotation database.

The caller supplies the four-file database root. Therefore database
redistribution permission is not a release prerequisite for the image. This
boundary does not remove the need to identify the supported database release
or validate the caller-owned files before annotation.

Open-source or non-commercial publication does not itself satisfy third-party
license obligations. This is an engineering release-readiness record, not
legal advice; repository maintainers accept it through normal exact-head
review and merge rather than a separate, undefined legal sign-off gate.

The hashes above identify reviewed local release inputs; the image build must
verify them rather than trusting filenames.

## Release Requirements

Publication is permitted only after the release branch contains and validates:

1. an exact dbCAN source repository and tag or commit corresponding to the
   installed 5.2.9 wheel;
2. the DIAMOND 2.1.15 source release reference and GPL license text;
3. a deterministic image build that verifies all downloaded or copied input
   hashes;
4. `LICENSES/` and `NOTICE` materials for every bundled component that requires
   them;
5. an SPDX or CycloneDX SBOM generated from the final image;
6. a source-correspondence table mapping bundled binaries and Python packages
   to exact upstream source locations;
7. a smoke annotation using a caller-mounted, read-only test resource;
8. publication to `ghcr.io/fuqingzh/seqevi-dbcan`, public anonymous pull, and
   digest readback from GHCR.

Mutable tags may be published for discovery, but SeqEvi manifests and profiles
must consume the verified digest reference.

## Database Boundary Verification

The final image and SBOM must contain none of:

```text
CAZy.dmnd
dbCAN.hmm
dbCAN-sub.hmm
fam-substrate-mapping.tsv
```

The smoke command bind-mounts an external resource directory read-only. A
successful smoke therefore proves runtime compatibility without turning the
database into a distributed image component.

## Current Disposition

The scientific adapter and real dbCAN 5.2.9 runtime behavior are accepted. The
public image is not yet releasable because its build, source mapping,
license/NOTICE bundle, final-image SBOM, digest smoke and anonymous-pull
evidence have not yet been produced. Those items belong to the managed
onboarding implementation slice; database redistribution review does not.
