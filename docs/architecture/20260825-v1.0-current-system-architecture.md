Version: v1.0

Status: approved target architecture; current overview

Applies to: SeqEvi 0.3.5 at `f8ce02d992ce3b7aa1c1b75ece7d1d96803bd54f`

Unreleased successor note (2026-08-31): the R2 working tree implements native

This overview is the current front door. It consolidates the implemented
product shape and routes readers to the detailed contracts; it does not
replace their scientific identity or compatibility rules.

## Product Boundary

SeqEvi is an independent, content-addressed protein-sequence evidence cache.
It reuses annotation evidence only when the complete immutable key matches:

```text
SequenceID
AdapterContractVersion
ToolRuntimeDigest
ResourceID
CanonicalSemanticParameters
```

One invocation selects one official adapter and publishes one self-describing
DuckDB result. Adapter-native schemas remain separate. Caller-owned annotation
databases remain outside SeqEvi and are never downloaded, copied, or bundled by
the scientific core.

The three official adapters are:

- `eggnog` for eggNOG-mapper;
- `interpro-pfam` for InterProScan/Pfam; and
- `dbcan-cazyme` for protein-level dbCAN CAZyme annotation.

## Public Surfaces

- Python: `seqevi.annotate(...)` and `seqevi.scan_annotations(...)`.
- CLI: `annotate`, `resource`, `profile`, `setup`, `serve`, and the four
  acknowledgement-bound `store-maintenance-*` commands.
- Result: one immutable DuckDB file containing adapter-native relations,
  sequence mapping, no-hit rows, metadata, semantic parameters, and run
  metrics.
- Store: local SQLite/POSIX or passive shared HTTP/PostgreSQL storage, with
  legacy POSIX and an explicit unreleased OCI Registry backend.

Direct adapter execution requires Python 3.12 or newer on Linux. `ToolRunner`
uses Linux `/proc` and `waitid` to fail closed while terminating and reaping an
external tool process group.

## Runtime And Distribution

Host profiles remain supported for all three adapters. Managed `seqevi setup`
is currently available only for `dbcan-cazyme`. It validates a caller-owned
four-file resource and delegates annotation to a digest-pinned first-party OCI
image. Docker remains outside the scientific domain model and is invoked only
at the application distribution edge.

The managed container receives narrow input, resource, output, and optional
Store mounts. Local-Store execution uses no network. An explicit shared
HTTP(S) Store enables container networking. Managed eggNOG and InterPro are not
implemented.

## Shared-Store Coordination

A claim-capable annotation opens one invocation-scoped `ClaimSession`.
ClaimSession suppresses duplicate active work, renews one session authority,
fences exact-key generations, and reconciles ambiguous finalization against
immutable terminal evidence. The shared Store remains passive and never
schedules annotation tools.

The internal route set is:

```text
/v1/internal/claim-sessions/{capabilities,open,renew,acquire,authority,finalize,close}
```

Released v0.2.0 clients retain the legacy lookup/fetch/commit surface against
legacy mode; OCI mode requires upgraded clients via capability admission. A legacy
commit may win against an active ClaimSession under the same exact-key lock;
the transaction retires the claim and immutable convergence prevents overwrite.

One public finalize call first stages uncached artifacts with independent
900-second total deadlines and at most 60-second HTTP phase timeouts. It then
captures fresh authority and one short metadata deadline shared by every split
batch and reconciliation. Split batches do not receive new finalize budgets.
Service upload filesystem operations run off the event loop under bounded
admission; cancellation retains ownership until I/O and cleanup finish.
OCI staging delegates transfer to pinned ORAS. OCI metadata finalize verifies
canonical manifest and blob descriptors without downloading the large layer;
download still fully checks raw size and SHA-256. Existing registered POSIX
bytes stay in place and local execution requires no Registry or ORAS.

## Known Incomplete Work

- The original public-user Slice D acquisition run remains incomplete and is
  not represented as a pass.
- Managed dbCAN has no claim-before-OCI path, so its D5 same-key managed gate is
  unavailable.
- InterPro v2 target-Store identity/exact-key refresh remains open before
  target-Store sanity.
- Global cache seeding remains incomplete.
- Public progress protocols, ETA, and multi-input scheduling remain later work.
