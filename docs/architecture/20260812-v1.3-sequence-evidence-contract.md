# Sequence Evidence Contract

Version: v1.3

Date: 2026-08-12

Status: proposed current-on-merge architecture; implementation in progress

Supersedes: [v1.2](20260810-v1.2-sequence-evidence-contract.md)

SeqEvi retains the v1.2 immutable `EvidenceKey`, artifact, evidence, lookup,
fetch, and legacy commit contracts. Claim coordination is invocation-scoped.
Each claim-capable annotation opens exactly one `ClaimSession`: an opaque
session ID, secret owner token, generation, and 120-second expiry. The client
renews one row at a nominal jittered 30-second cadence under a 90-second
request-start-anchored monotonic budget. Exact-key claims retain durable,
monotonically increasing generation fences.

The internal protocol is capability-gated at
`/v1/internal/claim-sessions/{capabilities,open,renew,acquire,finalize,close}`.
Acquire hashes canonical UTF-8 JSON for the actual ordered query array and is
idempotent by session/request ID. Close invalidates one session row; bounded
sweepers reclaim coordination later. The unreleased per-key HTTP protocol does
not exist. Capability absence selects v0.2.0 lookup/commit fallback for the
whole invocation, while old health, lookup, fetch, artifact, and commit requests
remain compatible.

PostgreSQL takes deduplicated signed advisory IDs in numeric order before stable
session-row locks. SQLite provides equivalent authority through database
serialization. Durable generation high-water tombstones are never swept.
